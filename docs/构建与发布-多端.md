# 星河音乐 · 多端构建与发布手册

> 版本：v1.0.0（版本号不随本轮迭代，构建产物与 `app/package.json` 严格一致）
> 适用：本机 Windows 出包 + GitHub Actions 跨端出包
> **原则：多端缺一不可。** 任一端缺失或版本号不一致，本轮视为未完成，禁止发布。

---

## 0. 版本号单一来源

| 位置 | 来源 | 说明 |
| --- | --- | --- |
| `app/package.json` → `version` | **唯一真源** | 所有端构建期读取 |
| `app/android/app/build.gradle` | 构建期读 package.json | `versionName` = version，`versionCode` = major×1000000 + minor×1000 + patch（1.0.0 → 1000000） |
| 渲染层「关于」页 | `__APP_VERSION__`（vite define） | 与 package.json 一致 |
| git tag / Release 标题 | `v{version}` | 与 package.json 一致 |

**校验命令（发布前必跑）**

```bash
cd app
node -e "console.log('pkg', require('./package.json').version)"
node -e "const v=require('./package.json').version.split('.').map(Number);console.log('versionCode', v[0]*1e6+v[1]*1e3+v[2])"
grep -n "versionName\|versionCode" android/app/build.gradle
```

## 1. 桌面端（Windows）

```bash
cd app
npm ci
npm run typecheck          # 必须 0 error
npm run build              # 渲染层 + 主进程 + 内置音源复制
npm run dist:portable      # 便携版 exe（推荐，免安装）
# 或 npm run dist           # portable + nsis 安装包
```

| 项 | 值 |
| --- | --- |
| 产物 | `app/dist/StarWish-1.0.0-win-portable.exe`（NSIS 另有 `StarWish-1.0.0-win-setup.exe`） |
| 资产命名 | **必须 ASCII**（`StarWish-<ver>-win-*`）。中文名会在 Windows→Ubuntu runner 的 zip/unzip 之间被解成乱码，且 GitHub 资产 URL 拒中文 |
| 冒烟 | `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS npx electron --no-sandbox scripts/smoke.cjs`（截图落 `app/dist/smoke/`） |
| 专项回归 | `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS npx electron --no-sandbox scripts/check-v236.cjs`（分P封面 / MV聚合 / 设置合并 / 主题市场 / 视频背景主题 / 分类筛选 / 搜索封面） |
| 本轮专项 | ① 返回栈：`npm run test:back-handler` 全绿（多级/replace/tab/弹层/失焦/音频模式）② 移动端真机：设置多级页返回逐级回退、左右边缘滑动返回、视频全屏锁横屏、音源启停「初始化中→就绪/失败」徽标、源市场 Tab/搜索/卸载 ③ 桌面：音源启停初始化 Toast、播放失败自动换源 |

**环境注意**：本机全局存在 `ELECTRON_RUN_AS_NODE=1` 与 `NODE_OPTIONS` 注入，运行 Electron 前必须 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS`；沙箱下需 `--no-sandbox`。

## 2. 安卓端（Android）

```bash
cd app
npm run build:mobile       # vite mobile 构建 + copy-wasm + rename-mobile-html
npm run mobile:sync        # cap sync android（把 dist/mobile 灌进 android/app/src/main/assets/public）
cd android && ./gradlew.bat assembleRelease assembleDebug
```

| 项 | 值 |
| --- | --- |
| 产物 | `app/android/app/build/outputs/apk/release/app-release.apk`（自签名）、`.../debug/app-debug.apk` |
| 发布资产名 | `StarWish-1.0.0-android.apk` |
| 版本校验 | `./platform-tools/adb.exe shell dumpsys package com.starwish.music \| grep version` |
| 真机安装 | `./platform-tools/adb.exe install -r app-release.apk` |

**硬性约束**

1. **release APK 只能本地出**：自签名 keystore `app/android/app/starwish-release.keystore` 被 `.gitignore` 排除，CI 无证书，只能 `assembleDebug`。release 包本地构建后手动补传到 Release。
2. **旧版本 APK 属错误版本**：构建前必须清理 `android/app/build/outputs/apk/{release,debug}/*.apk`，避免把上一轮（v1.0.0 早期快照）的包当成本轮产物发布。发布前用 `aapt dump badging` 或 `dumpsys package` 核对 `versionName=1.0.0`、`versionCode=1000000`。
3. **产物完整性断言**：APK 内 `assets/public/` 必须含 `index.html`、`cordova.js`、`assets/sql-wasm.wasm`（`unzip -l` 抽查），缺一即为坏包。

## 3. Linux / macOS（CI 出包）

`.github/workflows/release.yml` 在 `ubuntu-latest` / `macos-latest` 上产出：

| 端 | 产物 |
| --- | --- |
| Linux | `StarWish-1.0.0-linux.AppImage`、`StarWish-1.0.0-linux.deb` |
| macOS | `StarWish-1.0.0-mac-x64.dmg`、`StarWish-1.0.0-mac-arm64.dmg` |

CI 只做 `assembleDebug`（无 keystore），Android release APK 由本地补传。

## 4. 发布门禁（缺一不可）

| # | 端 | 产物 | 必须满足 |
| --- | --- | --- | --- |
| 1 | Windows 便携 | `StarWish-1.0.0-win-portable.exe` | 冒烟 0 error；专项回归全绿 |
| 2 | Windows 安装包 | `StarWish-1.0.0-win-setup.exe` | 同上 |
| 3 | Android | `StarWish-1.0.0-android.apk` | versionName/versionCode 对齐；真机可安装启动；核心页可进入 |
| 4 | Linux | AppImage + deb | CI 产出成功、体积非 0 |
| 5 | macOS | x64 + arm64 dmg | CI 产出成功、体积非 0 |

**任一端缺失 → 不发布。** 上传后逐个 `HEAD` 校验资产可下载（`curl -I` 返回 200 且 `Content-Length` 非 0）。

## 5. 推送与发布流程（删除旧推送新）

```bash
# 1) 提交
cd app && git add -A && git commit -m "feat(v1.0.0): <本轮内容>"

# 2) 清理本地旧 tag（v1.0.0 起为唯一 tag；远端历史已清空，直接推新）
git tag -l "v2.*" | xargs -r git tag -d

# 3) 推送 main + v1.0.0 tag（触发 CI 出 Linux/macOS 包）
git tag v1.0.0
git push origin main --tags

# 4) CI 完成后补传本地 Android release APK
#    gh release upload v1.0.0 StarWish-1.0.0-android.apk --clobber
#    gh release edit v1.0.0 --notes-file docs/StarWish-Music-v1.0.0-发布说明.md
```

**本机注意**：git 推送需 `-c http.sslVerify=false -c http.schannelCheckRevoke=false`；curl 访问 `api.github.com` / `uploads.github.com` 需 `--ssl-no-revoke`；本机无 `gh` CLI 时 token 取自 `git-credential-manager get`。

`gh release create` 在 Release 已存在时必失败；回退分支不能只 `gh release upload --clobber`（说明永远不更新），必须再 `gh release edit --notes-file`。
