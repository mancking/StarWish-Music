## 二、逐项证据明细

### 1. biu-master（B站音乐播放器）

- **技术栈**：`package.json` — `"description": "music application based on bilibili api"`，Electron 38 + React 19 + rsbuild + zustand。`plugins/` 目录是构建插件（electron-*.ts），**不是音源插件**。
- **音源协议 [已查证]**：
  - `src/service/player-playurl.ts:175-176`：`getPlayerPlayurl` → `GET /x/player/wbi/playurl`，参数含 bvid/cid/qn/fnval(DASH)，响应 `data.dash.{video[], audio[], flac, dolby}`。
  - `src/store/play-list.ts:306`：按 `currentPlayItem.type` 分流 —— `"mv"` 型用 `getDashUrl(bvid,cid)`；`"audio"` 型走 `getAudioUrl(sid)`（`src/common/utils/audio.ts:107`，调音频 web stream 接口）。
- **MV/视频判定 [已查证]**：
  - `src/common/utils/audio.ts:53-91`：拿到 DASH 后优先 flac→dolby→普通 audio，`audio.src = 选中的 dash.audio.baseUrl`；同段把 `dash.video[0]` 的 `baseUrl` 存成 `videoUrl`、分辨率存成 `videoResolution` —— **video 流从不送进 `<video>`，只落库给下载**。
  - 全 src 搜 `<video` / `VideoPlayer` / `dashVideo` 仅命中类型定义与下载弹层，**无任何视频播放组件**。结论：**不支持在线 MV 播放**。
- **视频聚合 [已查证]**：`src/pages/search/index.tsx:38-52` 默认 `SearchType.Video` + `User` 两个 Tab；`src/pages/video-collection/index.tsx:21` 视频收藏夹；多 P 下载选页弹层 `video-pages-download-select-modal/`（配合 package.json 的 `fluent-ffmpeg` 做音视频合并下载）。

### 2. keep-alive-master（音源插件集合，非播放器）

- **定位 [已查证]**：README 自述为洛雪/MusicFree 提供音源；`main.py` 只是带 `X-Request-Key` 头的转发壳。
- **音源协议-洛雪系 [已查证]** `render_api.js`：
  - 第 18 行 `const { EVENT_NAMES, request, on, send, utils, env, version } = globalThis.lx`
  - 第 57-63 行声明 `musicSources[item] = { name, type:'music', actions:['musicUrl'], qualitys:['128k','320k'] }`
  - 第 65 行 `on(EVENT_NAMES.request, ({action, source, info}) => … case 'musicUrl' …)`，第 84 行 `send(EVENT_NAMES.inited, {status:true, sources})`。返回体 `body.url` 即音频直链。
- **音源协议-MusicFree 系 [已查证]** `Music_Free/xiaoqiu.js`（QQ 音乐源）尾部：
  - `supportedSearchType: ["music","album","sheet","artist","lyric"]`
  - exports：`search / getMediaSource / getLyric / getAlbumInfo / getArtistWorks / importMusicSheet / getTopLists / …`。
  - 第 55 行 `12:"mv"` 仅为内部 `searchTypeMap`，`search()` 分支未实现 mv，且 `supportedSearchType` 不含 mv → **MV 搜索/播放不支持**。
- **结论**：纯音频音源插件包，无任何视频/MV 能力；价值在两套音源契约的方法签名样板。

### 3. SPlayer-dev（MV 支持最完整）

- **技术栈 [已查证]**：`package.json` `splayer 3.1.1`；`src/utils/request.ts:9` `baseURL = "/api/netease"`（NeteaseCloudMusicApi）；`.env.example` `VITE_API_URL=/api/netease`。
- **音源协议 [已查证]**：无用户插件，`src/api/` 按域拆分（album/artist/cloud/comment/lastfm/login/other/playlist/qqmusic/radio/rec/search/song/user/video）。
- **MV/视频支持 [已查证]**：
  - `src/api/video.ts:4-30`：`videoDetail(id, type:"mv"|"video")` → `/{type}/detail`（mv 用 `mvid`，video 用 `id`）；`videoUrl(id,type,r)` → `/{type}/url`；`videoDetailInfo` → `/{type}/detail/info`；`allMv(area,type,order,limit,offset)` → `/mv/all`。
  - `src/views/Video.vue:34` `<video ref="videoRef" />`，第 165/225 行 `new Plyr(...)`；第 242-265 行并发请求所有清晰度 `brs` 拼 `sources` 塞进 `videoPlayer.source`。
- **聚合入口 [已查证]**：
  - `src/components/Card/SongCard.vue:88-98`：`v-if="song?.mv"` 的「MV」warning 标签 → `router.push({name:'video', query:{id: song.mv}})`。
  - `src/api/search.ts:10-13`：`SearchTypes.Mv=1004, Video=1014`；router 中 `search-videos` / `artist-videos` / `like-videos` 三个子路由。
  - `src/views/Home/HomeOnline.vue:207`：首页个性化推荐里 `allMv` 拉一面 MV 墙。

### 4. agentxx-main（非音乐项目）

- **判定 [已查证]**：README 自述「C++ 协程异步实现的 AI Agent」；`agent/` 下为 tool_call 框架。grep `music` 仅命中 `test_openai_provider.cpp:1465+` 中 `musicxx_GetMediaInfo` 的 function-calling 测试字符串。
- **结论**：与音源/MV 无关，**不支持、不适用**。仅说明其插件框架后被拟声 extern_plugin 通用化（见 musicxx README）。

### 5. mediaxx-main（音视频能力库）

- **判定 [已查证]**：`src/mediaxx.h` 导出面 = `mediaxx_get_media_info_malloc`（读标题/艺术家/LRC/时长/专辑/年份）、`mediaxx_get_media_picture`（抽封面）、`mediaxx_analyse_picture_color*`（主/亮/暗色调）、`mediaxx_get_audio_visualization`（频谱）、`mediaxx_convert_char_encoding`、`mediaxx_get_available_hwcodec_list`。
- **结论**：只读元数据/封面/取色/频谱的 FFI 库，**无播放、无音源、无 MV**。对星河的价值在视觉层（封面取色、频谱、硬解探测）。

### 6. musicxx 拟声（含 extern_plugin 框架对照）

- **本快照范围 [已查证]**：`musicxx-main/server-cxx/src/myMusic/main.cpp` 仅打印 `add(7,77)` 的骨架；`vlog.md` 记录演进（2023/6 webdav → 2023/8 云盘+插件接口 → 2023/12 MediaManager → 2024/1 百度/阿里绑定）。**Flutter 客户端与 MV 实现在此压缩包中不存在**。
- **MV 能力 [一方称]**：README「支持播放绝大多数音视频格式；**支持视频MV、Anime4K 实时画质提升、逐帧播放**」「支持播放 bili 歌曲、本地、链接、webdav、各云盘、Subsonic、Jellyfin、Emby」。
- **音源协议 [已查证，来自 musicxx_extern_plugin 文档]**：
  - `docs/plugin-api.md:132`：歌曲只读视图字段含 `"video": [{ type, empty, durationMs, width, height, fps, size }]`（与 `audio[]` 并列）→ **音视频双流模型**。
  - `docs/plugin-hooks.md:120`：音源解析钩子，src 视图 `{type/empty/srcKey/quality/durationMs/hashMd5/size}`，可 `patch.src = {type:"Local|UrlLink|Bili|...", src, info}` 替换本轮音源，主程序自动试下一个源（多源回退）。
  - `docs/plugin-hooks.md:115`：切歌钩子载荷歌曲视图字段 `sid/name/artist/album/durationMs/.../srcKey/audio[]/video[]`。
- **结论**：MV/视频能力本身未能在代码层亲验（客户端未进包），但其**音源数据结构（audio[]+video[] 双流、srcKey 多源回退）**已在插件协议层留下实锤，最贴近星河「多音源聚合」的目标架构。

## 三、总结：对「视频 + MV 聚合」特色模块最有参考价值的项目

1. **SPlayer（首选，前端完整范本）** —— 它把 MV 当一等公民：歌曲对象带 `mv` 字段 → 卡片「MV」标签 → 独立全屏 `/video` 页（Plyr + 多清晰度并发取址 + 点赞/评论）→ 搜索 MV/视频 Tab → 首页 MV 推荐墙 → 歌手/收藏的 videos 子页。这套「歌曲↔MV 关联 + 独立视频页 + 多路入口」的信息架构可直接照搬到星河的视频聚合 Tab。其后端契约（`/mv/detail`、`/mv/url`、`/mv/all`、`/video/url`）是网易云系事实标准。

2. **musicxx 拟声（数据模型参考）** —— 其 `plugin-api.md` 中「一首歌 = 多个 src，每个 src 同时带 `audio[]` 与 `video[]` 流（含分辨率/帧率/大小）」的双流模型，以及钩子化 `patch.src` 多源回退，正好回答星河「多音源聚合时如何同时携带 MV 视频流」的结构问题：音频流负责听，video[] 负责一键切到 MV/视频播放。建议星河的音源返回结构直接采用「audio[] + video[] + srcKey 失败回退链」。

- **补充**：biu 的 B 站 DASH 取流（音视频分离、flac/dolby 档位、URL 120min 失效重取、WBI 签名）是接入 B 站系音源时的具体工程细节参考；keep-alive 给出洛雪/MusicFree 两套已有音源契约的方法签名；agentxx 与 mediaxx 与 MV 无关（分别是 AI Agent 框架与取色/频谱 FFI 库），只在星河做智能助手或播放页视觉时另行参考。
