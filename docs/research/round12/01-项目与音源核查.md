## ④ 六类核查结果（仅限上述范围）

**1. 代码有而用户使用无：**
- `starwish-bilibili.js` 的 `video` action（插件写了、宿主不调）——已记入 C-17。
- `media.ts:50 mediaUrl()`（导出无人调用）——已记入 N19。
- 桌面 `offlineVideoFile`（存了不读）——已记入 Bug 110。
- `mvVolume/mvQuality/mvRememberProgress/mvAutoNext` 设置项——已记入 F-15。
- 桌面 `video:save` 通道（`ipc.ts:520-530`，对话框另存 mp4）：渲染层 grep 无调用方——**死通道**（可能由旧版 UI 调用，现状无入口）。

**2. 用户使用而代码无：**
- 移动端 MV 离线缓存：`mobile/MvPlayer.vue` 全文无缓存按钮，桥接虽有 `saveVideoOffline`（`bridge:765-787`）但前端从不传参调用；`OfflineCache.vue:15` 注释称「移动端暂无视频离线缓存能力」——**能力有、入口无**。

## ⑤ 结论：对「视频 + MV 聚合」新章节的建设性建议

### 5.1 协议扩展点（落地顺序）

1. **先修契约（Bug 109/110 → 半天）**：离线缓存参数统一 + `selectPart` 接 `offline:file`。这是任何新 MV 源上线前的地基，否则新源缓存一样坏。
2. **抽象 MvSource 接口（C-16）**：以现有 `useVideoSession` 为模板，把 `call('music:mv' / 'mvinfo' / 'mvparts' / 'mvurl')` 四个调用点的参数从 `{bvid,cid,qn}` 改为 `{source, id, quality}`；后端 `music-service.ts:531-545` 改为分发器（按 source 路由到 bili / wy / qq providers）。
3. **lx 协议补 mv action（C-17）**：`lx-host` 增加 `dispatchMvSearch/dispatchMvUrl`，复用插件市场/订阅源通道——这样酷狗（需签名）等后续源可以**走插件分发而不必改主进程**。
4. **字段映射（N18）**：`MvItem` 扩 5 字段（source/sourceId/cover/durationSec/qualities 摘要），bvid 改 optional；B 站老数据做兼容映射。

### 5.2 可复用点（量化）

- **直接复用零改造**：VideoStage、useVideoGestures、PlaySettingsSheet、AudioModeView、DanmakuLayer、续播 localStorage 键逻辑（`:24-28,53-69`）、临时流缓存与 swmedia Range 206（`media.ts:300-339,380-418`）。
- **防盗链复用**：`media.ts:35-48 refererFor()` 已覆盖网易云（126.net/163.com）、QQ（gtimg.cn/qq.com）——N19 落地后两源 MV CDN 头注入零新增。
- **档位抽象**：现状 B 站 `accept_quality` 4-6 档（`providers.ts:1360-1367`）；**新源档位量化**：网易云 brs 4 档（240/480/720/1080，【一方称】10-24 实测）、QQ 3 档（【一方称】）、酷狗元数据可用但播放需签名（本期只展示不播放）、酷我需 token 签名（同）、咪咕放弃。统一档位表建议收敛到 ≤6 档 `{qn,label,url}`，默认「自动」映射到各源最高免登档。

### 5.3 风险点（量化时序）

- **时序现状**：`load()` = mvinfo(1 串行) + mvparts(1 串行) + mvurl(1 串行) + danmaku(并发) + related(并发) ≈ **2 串行 + 3 并发**；新源接入后保持同构（wy/qq 无分 P，parts 返回空数组即可走 `useVideoSession.load:130` 的兜底分支）。
- **直链时效**：B 站 playurl 小时级过期；网易云 brs / QQ GetMvUrls 同理——**离线缓存键必须用 `source:id:quality`（参照 `media.ts:172-174` sha1 键），绝不能用 url 当键**。
- **CSP/防盗链联调**：视频链路现状是直连 https（N19），桌面 `index.html:7` CSP `media-src` 未列 https——**【待联调】**现有 B 站直链若实际可播，说明该约束未对 `<video>` 生效；稳妥做法仍是统一走 swmedia 代理（`mediaUrl()` 已就绪，仅缺调用）。
- **参数契约先行**：Bug 109 的三端不一致必须先修，否则聚合后每个新源都会重复踩 save/remove 两个坑。
- **队列聚合（F-16）建议放二期**：先做单源播放链路 + 源 Tab（F-14），队列化依赖 MvItem 扩字段完成后再上。
