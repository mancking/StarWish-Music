## 二、各文档核心结论（压缩）

### 01 项目与音源核查（约 95% 已查证）
- **可复用零改造**：VideoStage、useVideoGestures、PlaySettingsSheet、AudioModeView、DanmakuLayer、续播键逻辑、swmedia 代理（Range 206 + Referer/Cookie 注入，refererFor 已覆盖 163/gtimg/qq/kugou/kuwo/bilibili/migu 域）。
- **音源现状**：lx 协议仅分发 musicSearch/musicUrl/lyric/pic；`starwish-bilibili.js` 声明的 `video` action 是死特性（宿主不 dispatch）；MvItem 仅 7 字段、无 source/mvId/vid；MV 四通道（music:mv/mvinfo/mvparts/mvurl）全部硬编码 B 站。
- **既有条目现状**：Bug 37（mvVolume 零消费）、Bug 47（selectPart 无请求令牌）、T-01（离线删除传参错→清空全部）、T-02（离线缓存缺 url→必抛错）——**全部未修，报错/误删路径已坐实**。
- **新编号**：Bug 109（离线三端参数契约不一致）、Bug 110（offline:file 存了不读）、C-16（MV 通道硬编码+路由只认 bvid）、C-17（lx 无 mv action 分发）、N18（MvItem 无法承载 mvId/vid）、N19（视频直链未走 swmedia 代理）、F-14（无源 Tab）、F-15（mv 设置四项空转）、F-16（无 MV 播放队列）。
- **落地顺序建议**：先修契约（Bug 109/110）→ 抽象 MvSource 接口（C-16）→ lx 补 mv action（C-17）→ 字段映射（N18）→ 代理化（N19）→ 源 Tab（F-14）→ 队列二期（F-16）。

### 02 落雪与 MusicFree（已查证）
- 落雪自定义源（user_api v2.0.0）**仅 musicUrl/lyric/pic 三种 action**，source key 白名单锁死，返回裸 URL；内置 SDK 硬编码五源；**零 `<video>` 组件，完全不支持 MV**。
- MusicFree 插件自由 platform：`getMediaSource` 返回 **`{url, headers, userAgent}` 防盗链头**（落雪没有，星河必须学）；bilibili 插件 `fnval=16` 只抽音频轨、音悦台 `searchType:"MV"` 把视频流当音频播——**两大项目都没有真 MV 播放器，星河做视频渲染正是差异化空间**。
- 启示：音源自声明 `capabilities.mvSearch/mvQualities`；清晰度档位（240p~1080p）替代音质档位；缓存键含清晰度 + no-cache（CDN URL 有时效）；沙箱学落雪隐藏 BrowserWindow + 宿主 HTTP 代理。

### 03 any-listen + 音源制作.txt + 网络（已查证为主）
- any-listen：pnpm monorepo，18 种 ResourceAction（musicSearch/musicUrl/...）统一 `resourceAction(action, params)` + VM 沙箱 + 宿主代理；**全文零 `<video>`，纯音频播放器**。
- 音源制作.txt（洛雪协议）：事件收发模式（`inited` 声明 sources/actions、`request` 回调必返 Promise、`lx.request` 无跨域限制、utils 提供 AES/MD5/RSA/zlib）；**协议本身无视频概念，MV 需扩展 type='video' + 分辨率维度 qualitys**。
- 网络（附 URL，见 03 文档）：NeteaseCloudMusicApi `/mv/detail`(mvid)、`/mv/url`(id, r 默认1080)、`/top/mv`、`/simi/mv`、`/mlog/music/rcmd`；QQMusicApi `/mv`(vid)、`/mv/url`(vid 批量直出可播链接)、`/song/mv`(songid→相关MV)、`/singer/mv`、`/search?t=12`。
- 聚合形式：QQ 播放页有 MV 才显示入口 + MV 巅峰榜；网易云 2026-05 新版播放页内嵌 MV 查看。
- 风控/合规：网易云逆向接口 2024 收律师函删库（npm/Gitee 镜像 2026-10 仍在维护）；QQ 系依赖绿钻 cookie；应用层设「仅元信息/解析地址」合规开关，沿用用户自导入音源模式规避版权责任。
- 协议建议：新增 `mvSearch/mvDetail/mvUrl/mvBySong/mvBySinger/mvRank/mvRecommend/mvSimilar` 8 个 action。

## 三、规格书 v4.8 修改点摘要（对应验收口径）

1. **2.17 MV 音源协议扩展（特色）**：lx-host 分发 mvSearch/mvUrl；音源 actions 扩展；MvItem 字段扩展；四源实现对照（网易/QQ/酷狗/酷我接口参数与档位）；`{url, headers, userAgent}` 防盗链；缓存键 `mv_{source}_{id}_{quality}`；合规开关。
2. **2.18 播放页 MV 按钮（特色）**：入口/显示条件/交互/数据流/记忆位置 `xinyuan_resume_mv_{source}_{mvId}`/车机隐藏。
3. **2.19 MV 与视频统一播放器规格（特色）**：统一媒体源模型、画质档位收敛 ≤6 档、弹幕仅 B站、相关推荐（mvBySinger/mvSimilar）、音频模式复用、缓存/下载复用。
4. **3.10 视频/MV 页 → 视频 Tab 聚合页（重写）**：源 Tab（B站/网易云/QQ/酷狗/酷我）+ MV 热榜/新歌 MV + 混合信息流 + 卡片源标 + 路由 `/mv/:source/:id` 兼容 `/mv/:bvid`。
5. **3.6 离线缓存**：新增 MV 离线缓存行（键/整片下载/离线可播，基于 Bug 109 契约修复）。
6. **4.2 视频四端差异**：新增 MV 按钮/MV 画质/MV 记忆位置/MV 离线缓存四行。
7. **5.0 Bug 修复专项**：新增「Bug 109~110 · C-16/C-17 · N18/N19 · F-14~F-16 · 第十二轮新增」。
8. **6.0**：新增 6.17 第十二轮调研（开源 MV 调研 + 音源 MV 实测 + round12 档案归位）。
9. **7.0 验收清单**：新增「视频+MV 聚合特色验收」块（8 项）。
10. **0.4 功能分级**：CORE 视频播放/页面两条补 MV 能力；**0.5 存储 Key**：新增 MV 记忆位置与 MV 播放设置两组键。
11. **版本三处同步**：title / ver div / footer → v4.8，footer 增补第十二轮说明。

## 五、证据说明与遗留事项

- **已查证**：01 约 95% 亲读源码带行号；02/03/04 逐文件核查带证据。
- **一方称**：网易云/QQ/酷狗/酷我 MV 接口可用性（2026-10-24 已实测打通，按要求直接引用未复测，可用性以规格书 v4.8 记录为准）；musicxx 支持 MV（快照不完整）。
