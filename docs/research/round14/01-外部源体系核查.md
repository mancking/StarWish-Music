## ③ 导入链路四条核查

### 3.a URL / 本地 JS 导入（lx-music 协议）

**现状（已查证）**：
- IPC 入口 `ipc.ts:272-276`（sources:import）→ `lxHost.importSource({url, content, file})`
- 校验：`lx-host.ts:526-537`
  - URL 必须 http(s)，`request()` 拉取，HTTP 非 200 抛错（529-531）
  - 内容空抛错（534）
  - 正则 `/lx\.|EVENT_NAMES|module\.exports|exports\./` 粗校验（535）
- 命名：解析头注释 `@name`，否则从 `script.name=` 提取，否则 `imported-${ts}`；非法字符替换，截 60 字符（538-543）
- 写盘：`userSourcesDir()` = `<userData>/sources/`（`paths.ts:124-126`），同名加 `-1/-2` 后缀（552-557）
- 原地更新：传 `file` 时要求目标存在且**非 builtin**（`lx-host.ts:547-551`：`if (!old || old.builtin) throw new Error('只能更新用户导入的音源')`）
- 写完 `this.load()` 重载（559），若新加载的脚本报 loadError 则抛错（561）
- 桌面端 IPC 后 `broadcast('sources:changed', lxHost.list())`（`ipc.ts:274`）

**断点**：
- 校验过弱（见 N-25）：任意含 `module.exports` 的非音源 JS 都会被写盘并 vm 执行；loadError 抛错但**文件已留在磁盘**，下次启动又会加载。
- 移动端 bridge 同通道（`mobile/bridge/index.ts:361-365`）已注册，但**移动端 Settings.vue 没有 UI 调用入口**（见 F-23）。
- 桌面 Settings.vue 调用：`Settings.vue:388` 传 `{url, content, file}`，与 IPC 解构匹配；更新替换弹窗由 `replaceTarget` 驱动（80, 387-399, 407-411）。

**功能名与代码匹配**：✅ 匹配。

**死代码**：`lx-host.ts:188` `dirs = [sourcesDir(), userSourcesDir()].filter(d => ...)` 在开发态两目录可能相同（`paths.ts:105-121` 候选回退到 `__dirname/../../sources` 即工程内 sources/），`seen` 集合去重；生产态 sourcesDir 在 `process.resourcesPath/sources`，userSourcesDir 在 `<userData>/sources`，两目录独立。OK。

### 3.b 插件市场（MusicFree 协议）

**现状（已查证）**：
- 官方 manifest：`https://raw.githubusercontent.com/mancking/StarWish-Music/Star-Wish-Plugin-Library/manifest.json`（`Settings.vue:97`）
- 桌面：`ipc.ts:307 plugins:market` → `mfHost.fetchMarket(url)`（`mf-host.ts:396-401`）
- 桌面镜像：`mf-host.ts:368-380 mirrorCandidates` 只把 raw.githubusercontent 改写为 cdn.jsdelivr.net（**主 + 1 镜像 = 2 个**）
- 移动端：`mobile/bridge/index.ts:194-244 fetchMarketManifest`，5 个镜像并发竞速（raw / fastly.jsdelivr / gh-proxy / raw.gitmirror / cdn.jsdelivr），winner URL 回写到每个 entry.url
- 安装：`Settings.vue:466` `call('plugins:import', {url: entry.url, origin: 'subscribe'})` → 桌面 `ipc.ts:298-302`
- 已安装插件「更新」：`Settings.vue:481` `call('plugins:import', {url: p.sourceUrl, file: p.file, origin: p.origin})` → `mfHost.importFromUrl(url, replaceFile)`（`mf-host.ts:263-270`）原地覆盖

**断点**：
- **桌面 `plugins:import` 丢弃 `origin` 参数**（见 Bug 121）：IPC 只解构 `{url, content, file}`，origin 被吞；导致市场安装的插件 origin 恒为 `'url'`，UI「·订阅」标签（`Settings.vue:1682`）永不显示。移动端 bridge（`index.ts:396-404`）正确接收 origin。
- **桌面镜像仅 2 个**（见 N-24），与移动端 5 镜像不对等。
- **插件默认关闭**（见 N-26）：`mf-host.ts:135-136,150-151` `enabled: entry.enabled === true`，新装插件必须用户手动 Toggle。
- **插件运行时死链**（见 Bug 120）：即便启用，`plugins:search/plugins:url/plugins:lyric` 三个 IPC **没有任何渲染层调用**，music-service.ts 也没 import mfHost。插件装了等于没装。

**功能名与代码匹配**：⚠️ 「插件市场」按钮拉取的 manifest 字段 `MarketEntry {name, file?, url, version?, author?, description?, platform?, supportedSearchType?, types?}`（`mf-host.ts:350-360`）与 Settings.vue 安装逻辑匹配。

**死代码**：`mf-host.ts:169` 注释「不再加载随包分发的内置插件」——代码里也确实没有 builtin 插件目录扫描（`loadAll` 只读 userPluginsDir），注释与实现一致。

### 3.d 更新替换 + 恢复内置音源

**现状（已查证）**：
- **更新替换的是用户导入的音源**：`lx-host.ts:547-551` 显式 `if (!old || old.builtin) throw new Error('只能更新用户导入的音源')`。内置音源不允许走「更新替换」通道。

## ④ 实时更新现状

### 4.1 导入完成即时生效

- 主进程内：`lx-host.importSource` 写完盘后立即 `this.load()`（`lx-host.ts:559`），内存中的 `this.sources` 已刷新。
- 桌面 IPC 后：`broadcast('sources:changed', lxHost.list())`（`ipc.ts:274`）。
- **但渲染层监听是断的**：
  - `src/stores/library.ts:51-53`：`on('sources:changed', () => { /* 音源变化由设置页自行刷新 */ })` —— **空函数**。
  - `Settings.vue` 里没有 `on('sources:changed')`，靠 await 返回值手动刷新 `sources.value = await call(...)`（`Settings.vue:318,339,359`）。
  - 搜索页 / 播放页 / 首页都不监听该事件。
- **结论**：在 Settings 页内导入后，Settings 列表本身会更新（因为 IPC 返回值带回了新 list）；但**其他已经打开的页面（如搜索页）不会重新拉取 `sources:platforms`**——反正它们本来也没用这个通道（见 Bug 123）。下一次搜索调用 `music:search` 时才会走主进程 `searchAll`，此时主进程的 `lxHost.sources` 已是新列表，所以**搜索/取链功能本身即时生效**。事件广播只是没消费者。

### 4.2 重启后自动加载已导入源

- 持久化位置：`<userData>/sources/*.js`（`paths.ts:124-126`）+ `<userData>/plugins-registry.json`（`paths.ts:134-136`）+ db 表 `sources.disabled` / `sources.deleted`（`ipc.ts:259-260`）。
- 启动时 `lxHost.load()` 扫描两个目录（`lx-host.ts:184-214`），`mfHost.init()` 扫描 plugins 目录（`mf-host.ts:449-455`）。
- ✅ 重启自动加载。
- ⚠️ 数据目录迁移时会 `fs.cpSync(oldDir/sources, newDir/sources)`（`ipc.ts:778`），但**没搬 plugins 目录和 plugins-registry.json**——切换数据目录后已安装的插件会丢失（见 N-27，待复核）。

### 4.4 失败降级链与 0.8.2 差距

- 已实现：质量链降级（flac→320k→128k，`music-service.ts:37-42 QUALITY_CHAIN`）；同 platform 多音源串行；跨平台同名搜索换源；播客直链短路；本地文件短路。

## ⑦ 对规格书「外部源体系」章节的建议

### 7.1 框架与源边界（量化）

| 类别 | 功能 | 依赖 |
|---|---|---|
| **无源可用（框架）** | 本地扫描/播放器内核/EQ/频谱/下载队列/设置/主题/缓存/壁纸/桌面歌词/WebDAV/B 站登录/数据目录迁移 | 0 |
| **半依赖（原生接口）** | 首页推荐/发现页歌单/榜单/新歌/私人电台 | wy/qq/kg/kw/mig 原生接口（providers.ts 硬编码），不算"导入音源" |
| **强依赖（外部音源）** | 在线搜索聚合/在线取链/在线播放 | lxHost（用户导入 + 内置 .js）|
| **硬编码 B 站（应外部化）** | Mv 搜索/详情/分P/取链/弹幕/离线视频 | 当前不抽象，未来接入 video action |

建议规格书明确：**"框架"= 第一类 + 第二类原生接口；"音源"= 第三类 lxHost；"视频源"= 第四类（未来）**。

### 7.2 导入→生效→持久化链路

```
URL/本地 JS → lxHost.importSource (lx-host.ts:526)
```
