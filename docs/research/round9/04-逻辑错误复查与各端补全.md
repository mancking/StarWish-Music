## A. 启动态逻辑复查（Bug55~Bug61）

### Bug55｜桌面 splash 过早消失，player/library 仍在后台未就绪
- 证据：`src/main.ts:82-83` `await ui.init().catch(() => {})` 后立即 `hideSplash()`；`:85` `void Promise.allSettled([player.init(), library.init()])` 才后台并行。ui.init 即便失败（catch 吞掉）splash 照样移除。此时首页推荐（Home.vue:183 onMounted 才 load）、曲库（library.ts:30-36 五连 call）尚未返回，用户看到的是空骨架/空收藏，点击「每日推荐」只能拿到 Home.vue:133 的「还在生成中」toast。
- 解决：hideSplash 挪到 Promise.allSettled 完成后（或维护 ready 计数器，三者全 settled 再淡出）；ui.init catch 失败时 splash 保留并在其上显示「设置加载失败，点我重试」按钮。
- 适用端：桌面。

### Bug56｜#splash 无任何超时兜底，任一 init 挂起则永驻
- 证据：`src/main.ts:74-89`（桌面 hideSplash 仅靠 ui.init resolve 触发）与 `src/main.mobile.ts:89-97`（`Promise.all([ui.init(), player.init(), library.init()])` 的 finally 才移除 splash；main.ts:82 同理）均无 timeout。IndexedDB 锁、sql.js wasm 挂起、settings:get IPC 不返回时，splash 永久驻留，用户只能强杀进程。
- 解决：两端 bootstrap 包 `Promise.race([allInits, timeout(8000)])`，超时强制 splash-out 并 toast「初始化较慢，界面已可使用，数据稍后补齐」。
- 适用端：全端。

### Bug57｜主进程启动失败路径不调用 markBootReady，渲染层每个 IPC 白等 20 秒
- 证据：`electron/main.ts:349` `markBootReady()` 仅在 bootstrap 成功路径执行；`:401-406` catch 分支只 `dialog.showErrorBox`，bootReadyPromise 永不 resolve。此后渲染层所有 call 都在 `electron/ipc.ts:866-871` 等满 `BOOT_TIMEOUT=20000` 才放行，放行时 DB 未初始化，handlers 全部抛错，界面持续报「数据库未就绪」。
- 解决：catch 分支末尾补 `markBootReady()`，并 broadcast('toast', {type:'error', message:'部分启动组件失败，请查看日志'})，让 IPC 走各自降级分支。
- 适用端：桌面。

### Bug58｜call() 无客户端超时、未防御 window.sw 缺失
- 证据：`src/api.ts:20` 直接 `await window.sw.invoke(...)`，既无 `window.sw` 存在性检查（桥未装好时抛原始 TypeError，被 :24-28 catch 后以未识别错误抛出），也无 promise 超时——主进程 gate 最多等 20s（ipc.ts:841），渲染层跟着等满，调用方无感知永久挂起。
- 解决：call 开头 `if (!(window as any).sw) throw new Error('应用组件尚未就绪，请稍后重试')`；invoke 包 `Promise.race([invoke, new Promise((_,r)=>setTimeout(()=>r(new Error('请求超时')), 15000))])`。
- 适用端：全端。

### Bug59｜移动端 installBridge 在 mount 前串行阻塞首帧，splash 无进度
- 证据：`src/main.mobile.ts:37` `await installBridge()` 完成后才 createApp/mount；`src/mobile/bridge/index.ts:55` `await patchNativeFetch()`、`:61` `await vfs.initFs()`、`:91` `await Promise.all([dbReady, lxReady])`（sql.js wasm 编译 + 音源沙箱加载）全部串行在静态 splash（index.html:36-45 仅一枚呼吸圆点）上等待，冷启动数秒无任何阶段反馈。
- 解决：splash HTML 增加阶段文案（「正在恢复本地数据…」「正在加载音源…」由 bridge 分阶段回调更新）；或改为先 mount 界面骨架，bridge 未就绪期 EngineGuard 遮罩。
- 适用端：移动。

### Bug60｜冷启动窗口底色与 splash 色差跳变
- 证据：`electron/windows.ts:43` `backgroundColor: '#0b0d12'`，而 `src/index.html:22` splash 背景 `#0b0f1a`；ready-to-show 触发前（windows.ts:122）窗口已显示一帧，两色存在肉眼可辨的深色跳变。
- 解决：统一为同一 hex（窗口 backgroundColor 改 #0b0f1a），消除首帧色差。
- 适用端：桌面。

### Bug61｜Local 页 onMounted 与 library.init 并发重复拉取本地曲库
- 证据：`src/pages/Local.vue:45-49` onMounted `await library.refreshLocal()`（call library:songs/count）与 `src/stores/library.ts:30-36` init 内的同款并发调用同时发起（桌面 main.ts:85 后台跑 library.init），冷启动双份 IPC；init 返回后页面 onMounted 的 refreshLocal 又覆盖一次结果，存在后到者覆盖先到者的竞态。
- 解决：onMounted 先判 `library.loading` 或 `library.localTotal > 0`，已就绪则跳过 refreshLocal，仅补拉 scanProgress。
- 适用端：桌面+移动。

## B. 各端功能补全（Bug62~Bug74）

### Bug62｜窗口 resize/move 持久化监听注册过晚
- 证据：`electron/main.ts:322` 已 `createMainWindow()` 并 `restoreWindowState`（:324），但 `:354-355` 的 `mainWin.on('resize'/'move', persistWindowState)` 直到 bootstrap 后期才注册——initDb/音源加载期间用户拖动窗口，位置不落库，下次启动仍是旧坐标。
- 解决：监听注册挪到 createMainWindow 返回后立即执行（main.ts:324 之后），或在 windows.ts 内部创建时即绑 resize/move 到 persist 回调。
- 适用端：桌面。

### Bug63｜托盘 tooltip 切歌滞后约 1.2 秒
- 证据：`electron/main.ts:373-384` player:state 广播按 1200ms 节流才 rebuildTrayMenu；而 `:231-235` 托盘 tooltip（trayTip）是在 rebuildTrayMenu 内部顺带更新的，切歌后 tooltip 显示旧歌名最长 1.2s，与任务栏/系统感知不一致。
- 解决：广播回调里检测 song.id 变化时单独 `tray.setToolTip(新曲名)`，跳过节流 rebuild。
- 适用端：桌面。

### Bug64｜installBridge 失败无兜底，boot reject 导致首帧永不挂载
- 证据：`src/main.mobile.ts:37` `await installBridge()` 无 catch；`src/mobile/bridge/index.ts:85` `dbReady = initDb().then(() => initBiliLogin())` 中 initDb（sql.js 打开 IndexedDB）reject 会沿 `:91` Promise.all 抛出，bootstrap 中断——createApp/mount 都没执行，界面空白 + splash 永驻。
- 解决：installBridge().catch 兜底：仍执行 mount 与界面骨架，toast「本地数据初始化失败，已进入临时模式」，在线音源浏览不受影响；恢复入口在设置页。
- 适用端：移动。

### Bug65｜车机播放页无缓冲/错误反馈
- 证据：`src/pages/CarPlayer.vue:36-49` info 区只渲染 `song?.name || '未在播放'` 与 singer，完全未消费 `player.state.error`（stores/player.ts:55）或加载态；弱网切歌/取链失败时屏幕仅显示旧歌名，驾驶中用户无法判断是否卡死。
- 解决：info 区歌名下方加琥珀色小字行：`{{ player.state.error || (player.playing ? '' : '缓冲中…') }}`。
- 适用端：车机。

### Bug66｜车机进度条仍可点击 seek，违背「驾驶勿扰」
- 证据：`src/pages/CarPlayer.vue:40-47` ProgressBar `variant="car"` 仍 `@seek="player.seekTo"`（:46）——驾驶中手指触到进度条任意位置即跳转播放位置，存在安全隐患（round8 规格书 Bug41 仅提出手势解绑，未落到进度条组件）。
- 解决：variant="car" 时 ProgressBar 内部 emit seek 前校验停车态/长按；或加 `:interactive="false"` prop 让车机档只显示不响应。
- 适用端：车机。

### Bug67｜车机页写死深色配色，日间强光下不可读
- 证据：`src/pages/CarPlayer.vue:72` `background: #0b0b10`、`:94-97` 标签、`:124-128` singer 全部硬编码，不跟随系统 prefers-color-scheme；阳光下车机屏深色底+琥珀字对比度不足。
- 解决：加 `@media (prefers-color-scheme: light)` 或日间开关：浅底（#fff3d6）深棕字（#5c4400），保持琥珀色主按钮。
- 适用端：车机。

### Bug68｜平板外接键盘方向键被绑为快进 5 秒，列表键盘导航不可用
- 证据：`src/App.vue:112-114` 无修饰键 ArrowRight → `seekTo(+5s)`、`:115-117` ArrowLeft → -5s，且 `:99` isTyping 仅跳过输入框；平板外接妙控键盘时用户想用方向键在歌曲列表移动选中却永远触发快进，与桌面端 mod+方向（:106-111）语义割裂。
- 解决：isPad 且焦点不在播放控制条时，ArrowRight/Left 改为「下一首/上一首」或列表选中移动，快进保留给 Ctrl+方向。
- 适用端：平板。

### Bug69｜window-all-closed 无 macOS 平台判断，关窗即退出违背 mac 惯例
- 证据：`electron/main.ts:418-420` `app.on('window-all-closed', () => { if (!getSettings().closeToTray) app.quit() })`——未按 `process.platform === 'darwin'` 分流；macOS 惯例关闭最后一个窗口不退出（dock 图标可重开），此处直接 quit，与 Windows/Linux 行为混一。
- 解决：回调内 `if (process.platform !== 'darwin' && !getSettings().closeToTray) app.quit()`；mac 下依赖已有 `:412-415` activate 分支重建窗口。
- 适用端：桌面。

### Bug70｜移动端双击退后台失败完全静默，用户不知应用仍在前台
- 证据：`src/mobile/back-handler.ts:24-28` `minimizeApp()` 的 `.catch(() => {})` 空吞；`:54-56` 双击命中分支直接 `minimizeApp()` 并把 `lastBackAt = 0`，moveTaskToBack 失败时无任何提示，用户以为已退后台实际应用仍驻前台继续发声，且需再等 2.2s 才能重试。
- 解决：catch 分支内 `ui.toast('退到后台失败，请按 Home 键')`；失败时不重置 lastBackAt，允许立即重试。
- 适用端：移动。

### Bug71｜手动车机开关 xinyuan_car=1 无清除入口，误开后永久锁死车机布局
- 证据：`src/platform/index.ts:81` `return lsGet('car') === '1'` 命中即强制 kind='car'（:85）；该键仅靠手动改 localStorage 设置，设置页与车机页均无清除入口（`isCarDevice()` :71-82 与 detectKind :84-89 无互逆路径）。
- 解决：设置-关于页加「重置布局模式」按钮 `lsSet('car','0')` 并 reload；CarPlayer 页右上角加「退出车机模式」小按钮（不干扰驾驶）。
- 适用端：移动。

### Bug72｜平板（移动包）KeepAlive 仅缓存 Home/Discover/Mv，其余页切换重复 mount 请求
- 证据：`src/App.vue:165-167`（移动模板）与 `:181-183`（桌面模板）KeepAlive `:include="['Home','Discover','Mv']"`；Mine/Favorites/History 每次切回都重新 onMounted 拉数据（Local.vue:45 onMounted refreshLocal、History/Favorites 同款），平板分屏/横屏快速切换时列表重复请求、滚动位置丢失。
- 解决：isPad 时 include 数组追加 'Mine'/'Favorites'/'History'（按注册 name），或改为按 route.meta.alive 动态收集。
- 适用端：平板。

### Bug73｜iPad（iOS）Local 页误显示「扫描系统音乐库」按钮，无 iOS 权限实现
- 证据：`src/pages/Local.vue:17` `mobile = platform.value.kind === 'phone' || 'pad'`；`:83-84` 移动端按钮文案「扫描系统音乐库」调用 `pickAndScan()`（:56-62）走 MediaStore；但 iOS 既无 Android MediaStore 也无 DocumentPicker 接入（round8 Bug10 已记录 ios 目录缺失），iPad 用户点了必然失败并弹权限 toast。
- 解决：platform 模型加 `os` 字段暴露 iOS；Local.vue 按钮按 `os==='ios'` 隐藏系统扫描，改显「从文件导入」（DocumentPicker）占位入口。
- 适用端：平板。

### Bug74｜车机播放页返回按钮在路由栈空时无兜底
- 证据：`src/pages/CarPlayer.vue:30-32` 唯一返回出口 `@click="router.back()"`；冷启动直达 /car（?platform=car 调试或车机系统默认路由）时 vue-router history.state.back 为 null（参考 back-handler.ts:46-50 的判据），点击无任何反应，驾驶中无法退出车机页。
- 解决：点击时先判 `router.options.history.state?.back == null`，为空则 `router.push('/')` 回主页；并按 Bug71 补退出车机模式入口。
- 适用端：车机。
