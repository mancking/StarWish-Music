## 一、启动体验与加载动画专项

### 启动动画规范（交付基线）
- 品牌动画：logo 呼吸 1.6s（`splash-breathe`）+ 闪烁点 1.2s（`splash-blink`）；splash 最短展示 800ms（防闪屏），**禁止假进度条**；浅色模式 `@media (prefers-color-scheme: light)` 已适配；`prefers-reduced-motion` 降级为静态展示；低端机（硬件并发≤4 或 deviceMemory≤2）主动移除动画 class。
- 原生↔Web 衔接：原生 splash 保持到 Web 首帧；两端底色 hex 统一（深 `#0b0f1a` / 浅 `#f4f6fb`），logo 同尺寸同心。
- 超时兜底：init 硬超时 8s 强制淡出，超时后提示「部分音源加载较慢」。
- 对标结论（来源见 01 文件）：LX Music 采用 ready-to-show 同策略；Musify 双 splash 首帧即消失；Spotify 闪屏、网易云 6~7s 长屏为反面案例——原生 splash 应保持到 Web 首帧，不可超过 1.5s 无反馈。

## 五、结论与修复优先级

1. **启动体验（用户核心诉求）**：先落 Bug55（splash 过早消失）、Bug56（超时兜底）、Bug60/窗底色统一；再装 `@capacitor/splash-screen` 做原生→Web 衔接（Android）；车机补内联 splash。全端执行「splash 最短 800ms、超时 8s 强退、禁止假进度条」规范。
2. **高频 BUG 对照**：T1（后台被杀）与 T2（通知栏失控）最高风险，根因同源——移动端无原生 MediaSession/前台服务，建议作为移动端下一迭代主项；T5（离线缓存无上限）桌面高优。
3. **引用复查**：C-04（历史静默丢失，用户可感知）最先修，C-05 次之，C-06/C-07 顺手清理。
4. **逻辑补全 20 条**：按「用户可感知→安全→工程」排序——Bug55/56/58/61/63 先落地；车机 Bug66 涉驾驶安全应优先，Bug67 涉及日间可用性，同批处理。
