# 02 - 开源项目音源治理机制调研（round13）

> 主题：治理内置音源风险——外部化 / 插件化 / 运行时隔离 / 失败降级 / 调试 / 体积控制。
> 目的：为星河音乐「音源外部化 + 运行时隔离 + 失败降级」方案提供可借鉴机制。
> 证据标注：【已查证】= 本轮亲自读过源码；【一方称】= 来自 README/CHANGELOG 等自述，未逐行核对。

## ② 可借鉴机制清单（对星河的适配建议）

| # | 机制 | 开源实现要点（证据） | 对星河的适配建议 | 次生问题提示 |
|---|---|---|---|---|
| 1 | **官方零内置音源** | lx `config/index.ts:2` 空数组；`api-source-info.ts` 全注释；MusicFree 仅内置 localFilePlugin；any-listen 仅内置 webdav | 星河 v1.0 不要在安装包里塞任何网络音源脚本；内置音源只放「本地文件解析」这一个零网络插件，把法律/合规风险完全外置 | 空包用户打开后没有歌可听 → 需要一份「音源推荐清单」文档（社区维护的 URL 列表），别把清单写进安装包 |
| 2 | **隐藏 BrowserWindow / 独立进程沙箱** | lx `userApi/main.ts:74-100`：show:false + contextIsolation + 禁 nodeIntegration + 禁 webgl/images + deny 导航/打开新窗 + data: URL | 星河若走 Electron：复刻这套——一个常驻隐藏 `BrowserWindow`，`webPreferences:{contextIsolation:true,nodeIntegration:true(preload),sandbox:false,webgl:false,images:false}`；denyEvents 列表照抄；关闭时清 storage | Electron 单 win 多源切换需要先 `closeWindow()` 清缓存再 `createWindow()`，切换会闪一下；多源并发播放要给每个源一个 BrowserWindow，内存成本要算 |

## ③ 反模式提醒（开源踩过的坑）

1. **音源失效连坐 / 切源风暴 → 被服务端封 IP**
   - 证据：keep-alive README:10-14 明说「反复请求可能会导致封禁 IP」「尽量避免频繁切换歌曲，否则将导致封禁 IP」；README:18 建议 MusicFree 用户开启「播放失败时暂停」。
   - 教训：星河降级链**不能**在用户无感知时疯狂换源重试；每次自动切源要 toast 提示，且同一首歌 5s 内最多切 1 次源；遇到 429/`tooManyRequests` 必须立即停手（lx `utils.ts:282` 就是这么做的），别把自己送进 IP 黑名单。

2. **市场地址单点失效 = 用户集体失联**
   - 证据：lx-source README:49-105 列了原始链接 + 6 个加速镜像（ghproxy.net / llkk.cc / moeyy.xyz / ghproxy.cn / 99988866.xyz / ghp.ci / gh-proxy.org），原因就是 GitHub raw 经常被墙；any-listen 的 `mirrorRequest` 也是为镜像设计的（`onlineList.ts:4`）。
   - 教训：星河的 sources.json 订阅 URL 至少备 2 个镜像；市场拉取失败时**静默 fallback 到上一次缓存**（any-listen `onlineList.ts:12-19` 就是内存缓存），别弹「市场不可用」就完事。

3. **沙箱逃逸 / 权限越界**
   - 证据：MusicFree 的 Function 沙箱（`plugin.ts:935-949`）其实**不是真沙箱**——插件代码跑在主 JS 线程里，能闭包捕获到注入的 axios/cheerio 等强引用，恶意插件可以遍历原型链搞事情；any-listen 之所以换成 Node `vm` + `codeGeneration:{strings:false,wasm:false}` + 路径穿越校验（`isolateContext.ts:129-132, 243-244`），就是因为 Function 沙箱不够硬。
   - 教训：星河不要满足于 MusicFree 那种「闭包注入 require」的伪沙箱；Electron 下用 lx 的「隐藏 BrowserWindow + contextIsolation」方案，或 any-listen 的 Node vm + 完整 host 函数表方案。在 Web 端（星河可能有 Web 版）必须用 Web Worker + OffscreenCanvas 隔离。

4. **体积膨胀：插件全量加载 / 无版本清理**
   - 证据：MusicFree 如果不开 `basic.lazyLoadPlugin`，启动时同步 readFile + `new Plugin(funcCode)`（即 `Function(...)` 编译）每个插件（`index.ts:129-135`），插件一多启动就卡；lx 把脚本 deflate 存盘也是为了减小体积（`userApi/utils.ts:90-98`）。
   - 教训：星河默认开启懒加载；插件目录里的旧版本 .js 要在升级时删掉（MusicFree `index.ts:239, 334` `unlink(oldVersionPlugin.path)`）；用户卸载插件时连插件私有数据一起清（MusicFree `index.ts:391-393` `removeAllMediaExtra`）。

5. **插件崩溃拖垮主程序**
   - 证据：MusicFree 在 `mountPlugin` 外层包 try/catch，失败塞 stub（`plugin.ts:966-988`）；musicxx `example_native_fail` 演示「钩子处理器一直失败 → 只记统计不卸载」（README:744）；any-listen vm `timeout:5000` 直接中断死循环脚本（`vm/index.ts:111`）。
   - 教训：星河任何音源脚本的同步异常/未 reject Promise/死循环都不能带崩 UI；入口脚本必须有 vm timeout 或 Worker.terminate 兜底；单次调用外层包 try/catch 并返回 null/空列表。

6. **自动更新把恶意/过期包装上**
   - 证据：MusicFree 用 sha256 去重 + semver 拒绝降级（`index.ts:215-230`），但**没有签名校验**——订阅源 URL 被中间人改包就能下发恶意脚本；any-listen 是少数做了 sha256 + RSA 签名双校验的（`shared/index.ts:226-230, 257`）。
   - 教训：星河若做自动更新，sha256 是底线，签名校验是进阶；同时要允许用户关掉「自动更新」，保留手动确认一步。

7. **把第三方后端写死进音源脚本 = 音源跟着后端一起死**
   - 证据：keep-alive 的 `render_api.js:8` 写死 `API_URL='https://lxmusicapi.onrender.com'`，Render 免费实例休眠/关停后整个源就挂；lx-source README 里 huibq 源就是引用 keep-alive 后端（README:109）。
   - 教训：星河官方文档要引导音源作者把后端 URL 做成脚本可配置项（或脚本自带多后端 fallback），别让用户装完一个源 = 押宝一个人的小服务器。
