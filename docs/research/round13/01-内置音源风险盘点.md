## ② 音源管理器 / 执行隔离现状（lx-host.ts）

### 加载与执行方式
- 启动期同步扫描两个目录 `[resources/sources, %APPDATA%/StarWish/sources]`，按文件名排序去重（`seen`/`deleted`）后逐个 `fs.readFileSync` + 执行（lx-host.ts:184-214）。主进程 boot 串行：`initDb() → lxHost.load()`（main.ts:327-331）。
- 每个音源在 **vm.createContext 沙箱** 内 `vm.runInContext(code, ctx, {timeout:20000})`（:271-272）；沙箱不含 require/process/fs，隔离设计存在。
- **但**：沙箱内 `setTimeout/setInterval/clearTimeout/clearInterval` 直接引用宿主函数（:221-224），`Buffer/Promise/URL/TextEncoder…` 也是宿主对象（:225-259）；加载超时 20s 只管加载期同步执行，**异步 handler 的 Promise.race 超时不 abort 底层 fetch**（:408-415、:476-479），超时后请求继续在后台跑（泄露连接）。
- 异常隔离：加载异常记 `loadError` 不再参与后续（:273-275、:368）；单音源抛错不拖垮主进程——**已查证**。
- 平台清单从 `state.inited` 解析（:277-287）；**`updateAlerts` 在 :145 被收集，但 loadOne 返回后 state 即被丢弃，全宿主再无读取**——长青 checkUpdate / 野草野花远程清单带来的「远程更新提示」是死通道（:145 vs :277-305）。
- `currentScriptInfo` 全部置空（:155）→ 墨澜 `@tx_cookie/@wy_cookie` 头注解解析（墨澜:25-42）永远拿到空 rawScript → cookie 解锁母带能力在本宿主永久关闭。

### 多源并发聚合
- 搜索：每源每平台一个 task，`try/catch` 包裹后 `Promise.all`（:406-461）——等价于 allSettled，单源失败不影响其他源，**已查证**。
- 每源搜索超时 `Promise.race` 默认 **12s**（:391）；外层 `waitMs` 到时即返回已收集结果，慢源后台继续（:456-461）。
- 取链：**串行**遍历候选源，每个 `Promise.race` 15s（:465-487）；无并发竞速——候选越多越慢（见 ⑤ Bug 116/117）。
- 歌词 12s（:489-505）、封面 8s（:507-523），均串行逐源尝试。
- 音源内请求：`lx.request` 默认 15s、`retry:0`（:111-112），失败时回结构化错误体不抛（:128-137）。

### 调试手段现状
- **沙箱 console 全为空函数**（:220 `console:{log(){},warn(){},error(){},info(){},debug(){}}`）→ 音源内 `console.log('星愿内置音源 已加载')`（星愿内置音源.js:159）实际不可见。
- 宿主侧只有：加载失败 `logger.warn('音源加载失败'/'音源加载完成 ok/total')`（:206,:305,:213）；http 层 `logger.warn('请求失败', url, msg)`（http.ts:253）。
- **无** per-source 请求日志、无音源错误上报开关、无请求体回显、无 debug 开关——音源失效时无法区分「接口挂/被风控/脚本错」（见 ⑤ F-17）。

## ③ 耦合与降级链现状

### 播放链路受影响路径
1. `player-service.load()` → `music-service.resolveUrl()`（player-service.ts:265）。
2. resolveUrl：先按 `QUALITY_CHAIN`（flac24bit→flac→320k→128k，music-service.ts:37-42）逐档 `lxHost.resolveUrl()`（:214-223）；全部失败且开了自动换源 → 按「歌名+歌手」再搜索、挑 4 个候选 ×2 档再取链（:229-255）。
3. 失败重试：首次取链失败 500ms 后重试一次（player-service.ts:290-293）；`handlePlaybackError` 最多 2 次带 avoid 换源重试（:311-321）；连续 3 首失败 → 暂停+toast（:323-326）。
4. **最坏耗时模型**（已查证推算）：候选源数 N（wy 平台当前活跃源可达 6+：星愿/统一/墨澜/长青/星海×2/特供）× 15s × quality 档数(≤2) × player 重试(≤2) ≈ 数百秒才报「无法播放」，期间 UI 停在 loading。
5. B 站歌：resolveUrl 直接走**原生** `biliAudioUrl`（music-service.ts:192-201），不经 starwish-bilibili 音源；该音源只贡献搜索结果，其 `video` action（starwish-bilibili.js:80,:94）在宿主无人调用——死代码。
6. MV 链路全部走 bili.ts 原生（music-service.ts:531-545），与内置音源无耦合。
7. 歌词：先 `lxHost.getLyric()` 再走平台原生（music-service.ts:369-373），失败静默降级，**无**音源健康度统计/展示。
8. 封面：`cover.ts:190` 也挂了 `lxHost.getPic()` 兜底。
9. **无「音源健康度/总降级开关」**：只有逐源启停（settings:toggle）与「自动换源」总开关（Settings.vue:1492）。

### 搜索链路
- 原生（wy/qq/kg）与插件并行，插件 `waitMs:2600-3500` 早退（music-service.ts:125,:147）——聚合搜索被插件慢源拖住的风险已控制；**已查证**。

## ④ 设置链路与体积现状

### 设置页（桌面 Settings.vue / 移动 mobile/Settings.vue）
- 音源列表/启停/删除/恢复：`sources:list|toggle|delete|restore`（ipc.ts:258-291）；「恢复内置音源」= 清空 deleted+disabled 并持久化为空数组（ipc.ts:285-290；lx-host.ts:330-334）。**内置源物理文件不删除**（lx-host.ts:568-572 仅标记）。
- 导入：URL（http/https）或本地 JS 内容，写 `%APPDATA%/StarWish/sources`；只允许更新用户导入源，**内置源禁止原地更新**（lx-host.ts:547-551）。校验仅正则 `/lx\.|EVENT_NAMES|module\.exports|exports\./`（:535），无大小限制/域名白名单。
- 插件市场：桌面/mobile 各自**硬编码** `OFFICIAL_SUB_URL = https://raw.githubusercontent.com/mancking/StarWish-Music/Star-Wish-Plugin-Library/manifest.json`（Settings.vue:97、mobile/Settings.vue:117）。桌面经 `mf-host.fetchMarket` 仅 raw→cdn.jsdelivr.net 单镜像兜底（mf-host.ts:368-401）；移动端有 5 镜像竞速（bridge:194-245）。
- 订阅源：纯用户自填 URL（`plugins:subscribe`，ipc.ts:303-306），无内置订阅地址。

### 打包与体积
- **桌面**：`package.json → build.extraResources`：`{from:"sources", to:"sources", filter:["**/*.js"]}` → **安装包 resources/sources 内含全部 11 个 JS（≈303 KB）**。
- **移动端**：`src/mobile/seed.ts:16-27` 用 `import.meta.glob('../../sources/*.js', {query:'?raw', eager:true})` 把 sources 原文**内联进 renderer bundle**（→ APK/IPA JS 体积 +≈303 KB）。
- git 现状：`git ls-files app/sources/` 仅 README.md + starwish-bilibili + starwish-unified 入库；第三方 9 个被 gitignore（`git check-ignore` 命中）。README（:14）与 seed.ts:8-10 都自述「第三方音源不随源码分发」——**与实际打包行为矛盾**：本机构建/分发包会把本地 9 个第三方脚本全部打进去（见 ⑤ Bug 111）。

## ⑥ 治理建议摘要（供规格书新章节引用）

1. **包内音源白名单化**（对应 Bug 111/112/C-18）：随包仅保留自研 3 源；第三方 8 源要么彻底移出安装包（首次使用从插件市场/订阅拉取），要么全部默认 disabled 并由用户显式启用。混淆 3 源（野草/野花/长青）建议直接不进包——不可审计即不可分发。
2. **断同源效应**（Bug 113/N22）：把 oiapi.net、zddyr.top、gdstudio.xyz 等共用后端画成「后端依赖图」，设置页音源列表展示每个源的后端域名与健康状态，避免「多源聚合」错觉。
3. **宿主补两件事**：a) updateAlert 落地展示（C-19，否则别让音源启动期乱发远程请求）；b) 音源 debug 日志开关（F-17），console 不再全空。
4. **取链预算硬顶**（Bug 117）：总预算 30s，超时 abort；候选源改为「竞速+择优」而非串行轮询。
5. **清理死承诺**（Bug 114/F-19）：B 站音源要么补 wbi 签名与登录态注入，要么下架；iTunes 试听源标注真实音质。
6. **市场/订阅地址外置**（N20）：manifest URL 配置化，默认多镜像竞速（移动端 bridge:194 已有现成实现，桌面 mf-host.ts 补齐）。
7. **验收基线**：任何版本发版前 grep 安装包 resources/sources 与 APK bundle，确认无他人密钥、无混淆体、无裸 IP HTTP。
