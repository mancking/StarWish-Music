## 三、统一源市场规格（写入规格书 0.10，要点）

### 0.10.1 市场形态与 git 分支分发通道
- 统一源市场 = 单一入口管理全部第三方源（音源/插件/视频源），dshmark 形态；五条分发通道：URL 导入 / 本地 JS 导入 / 订阅源（含自动刷新）/ 市场目录（多镜像竞速）/ git 分支分发。
- **git 分支分发现状（已坐实）**：插件库 = 同一 repo `mancking/StarWish-Music` 的 `Star-Wish-Plugin-Library` 分支（非独立仓库、非 submodule）；分支根目录放 9 个 .js + manifest.json + README；OFFICIAL_SUB_URL 拆解 = `<raw>/mancking/StarWish-Music/Star-Wish-Plugin-Library/manifest.json`；无 CI 生成 manifest、无 workflow 触发。
- **运行时无 git 客户端**（package.json 无 simple-git/isomorphic-git；electron/ grep 零命中）：App 纯走 HTTP raw 下载 → 同名覆盖。**0.10 决策：不引入真 git 协议**（isomorphic-git +~2MB 包体、移动端 WebView fs 支持有限），git 分支继续作托管方式，App 侧补齐版本/回滚/鉴权/缓存协议。
- **plugins:market 与 git 分支关系**：plugins:market 拉取的 manifest 即 git 分支根目录 manifest.json；市场目录条目 url = 同分支 raw 直链；0.10 后市场后端可指向任意 git 分支/仓库或静态托管，条目协议不变。

### 0.10.2 统一数据模型（MarketEntry v2）
- 字段：`kind`（lx-source | musicfree-plugin | video-source，缺省按协议字段推断，默认 musicfree-plugin 向后兼容）、`id`、`name`、`version`、`author`、`platform`、`description`、`icon`、`url`、`hash`（sha256）、`size`、`compat`（协议标识 + minAppVersion）、`changelog`、`commitSha`、`origin`（market | subscribe | local | url）。
- 兼容现有 manifest（mf-host.ts:350-360 字段）与订阅条目：旧条目无 kind 时由协议字段推断（含 musicSearch→lx-source；含 platform/search/getMediaSource→musicfree-plugin；含 videoSearch→video-source）。
- 适配器缺失提示：kind=video-source 且宿主无 videoHost → 明确「适配器缺失：当前版本不支持视频源，请升级」而非静默失败。

### 0.10.3 市场 UI（桌面 + 移动端对等）
- 单一「源市场」页面（桌面设置内 + 移动端对应入口）：Tab 过滤（全部/音源/插件/视频源）、搜索框、版本对比（可更新 badge + changelog）、一键安装/更新/卸载/禁用、来源标注（市场/订阅/本地/URL）、详情页（F-29）。
- 已安装分栏：已装（卸载/禁用/更新/回滚）+ 可发现；已安装判断按 kind+id / sourceUrl（Bug 125/126）。
- 移动端补齐与桌面对等入口（F-27/F-28/F-23 落地）。

### 0.10.4 通道矩阵（三类源 × 五通道全打通）
| 通道 | 音源 lx-source | 插件 musicfree-plugin | 视频源 video-source |
|---|---|---|---|
| URL 导入 | 通（现状 lx-host.ts:526） | 通（现状 mf-host.ts:222） | **新增** videoHost 分发 |
| 本地 JS 导入 | 通（现状） | 通（现状） | **新增** |
| 订阅源 | 通（刷新待补 C-25） | 通（刷新待补） | **新增** |
| 市场目录 | **新增** kind 分发 | 通（现状） | **新增** |
| git 分支分发 | 通（raw 现状） | 通（raw 现状） | **新增** |
- 视频源全通道新增 = C-24/C-28 落地：videoHost.ts 抽象 + lx-host 补 videoSearch/videoInfo/videoParts/videoUrl 分发（0.9.6 已有协议定义）。

### 0.10.5 宿主适配层（market:* 门面）
- 收敛 16+ IPC（C-26）：`market:list / market:search / market:install / market:update / market:uninstall / market:toggle / market:detail / market:channels`；旧 sources:* / plugins:* 保留向后兼容。
- 分发包按 kind 路由：lx-source→lxHost、musicfree-plugin→mfHost、video-source→videoHost（F-31 的 marketHost.ts 门面落地）。
- 关键限制（02 取证）：lx 协议纯 URL 解析器无 search、**取流不支持自定义 headers** → 视频站类源必须走 mfHost 形态插件（bilibili 插件范式：video=album、fnval:16 DASH 抽 audio[]、headers 透传）；市场对 video-source 条目强制协议标识。

### 0.10.6 原子性与缓存
- 安装原子：先写 .tmp 再 rename + sha256 校验 + semver 降级保护（Bug 124，对齐 MusicFree 先写新再删旧）。
- 更新原子：写盘前备份 .bak.<timestamp> → 写新版 → 校验 → 成功删备份/失败 restore（Bug 127 落地，对齐 any-listen 事务式更新）。
- 缓存：`<userData>/plugins/.cache/<sha1(url+content)>` 命中跳过下载（F-32）；市场目录磁盘缓存 24h TTL（OctoPrint repository_ttl 口径）；订阅条目 updatedAt 变化提示新版本。
- 鉴权：settings 加 gitToken，http.ts 请求自动带 Authorization（N31）。

### 0.10.7 合规与默认市场地址
- **空默认 + 用户配置**：默认市场地址为空或指向自建 manifest；不内置任何第三方平台音源（LX 2023-10 移除内置源、MusicFree 官方仓库告知函下架先例）；国内厂商取链清单仅允许用户自填订阅 URL。
- 市场地址可配置（设置项，N29 落地）；多市场 = manifest 数组 {name,url}（MusicFree subscribeUrl 范式）。
- 安全四件套（对齐 VS Code）：sha256 签名校验 / 沙箱加载前扫描 / 举报通道 / 下架自动禁用。

### 0.10.8 一次开发完成清单（全部必做，无二期）
- **大改动（3）**：marketHost.ts 门面（F-31/C-26 落地）、videoHost.ts 视频抽象（C-24/C-28 落地）、移动端源市场 UI 对等（F-27/F-28/F-23 落地）。
- **中改动（6）**：manifest kind 兼容（C-27）、市场页重构（搜索/Tab/详情/N28/N29/N30）、订阅刷新与卸载联动（C-25/F-30）、git 版本协议（minAppVersion/changelog/commitSha，C-28）、缓存与原子写（Bug 124/127/F-32）、gitToken 鉴权（N31）。
- **小改动（17）**：已安装判断 sourceUrl 化（Bug 125/126）、渠道 origin 标注、移动端 bridge 对等 IPC、空态/详情渲染等（详见 01 §④）。
- **明确不做**：不引入真 git 客户端协议（simple-git/isomorphic-git）；不做 WASM 插件框架；不做云服务端市场（自建 manifest 静态托管即可）；不默认收录侵权源；不新增重型依赖。
- 验收 = 7.0「统一源市场验收（第十五轮）」。
