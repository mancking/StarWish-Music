## ① 插件市场现状完整梳理

### 1.1 manifest 格式（MarketEntry 全部字段）

**主进程类型定义** `electron/core/mf-host.ts:350-360`：

| 字段 | 类型 | 必填 | 含义 | 渲染层使用位置 |
|---|---|---|---|---|
| `name` | string | ✅ | 市场条目名 | `Settings.vue:2055`, `mobile/Settings.vue:602` |
| `url` | string | ✅ | 插件脚本直链（http(s)） | `Settings.vue:466`, `mobile:173` |
| `file` | string? | ❌ | 期望安装后的文件名 | `Settings.vue:458-460 isInstalled` 比对 key |
| `version` | string? | ❌ | 版本号 | `Settings.vue:2056`, `mobile:603` |
| `author` | string? | ❌ | 作者 | `Settings.vue:2062`, `mobile:606` |
| `description` | string? | ❌ | 一句话介绍 | `Settings.vue:2063`, `mobile:606` |
| `platform` | string? | ❌ | MusicFree platform 名 | 渲染层未使用 |
| `supportedSearchType` | string[]? | ❌ | music/lyric/album/artist/sheet/comment | 渲染层未使用（实际用 `types`） |
| `types` | string[]? | ❌ | 显示用搜索类型标签 | `Settings.vue:2059` |

**渲染层本地 type 定义** `Settings.vue:106`：
```ts
type MarketEntry = { name: string; file: string; version?: string; author?: string; platform?: string; description?: string; types?: string[]; url: string }
```
`mobile/Settings.vue:118-127` 同构。

**字段缺陷**（影响统一市场）：
- ❌ **无 `kind` / `type` 字段**区分 `'lx-source' | 'musicfree-plugin' | 'video-source'`——主进程收到 manifest 不知道该走 `lxHost.importSource` 还是 `mfHost.importFromUrl`（见 C-27）。
- ❌ **无 `changelog` / `screenshot` / `permissions`** 字段（见 F-29）。
- ❌ **无 `minAppVersion` / `maxAppVersion`** 兼容性字段。

- 接受数组或 `{plugins: [...]}` 对象；

## ⑤ 新编号问题清单

### Bug 124 · 插件安装/卸载非原子，留孤儿文件或幽灵注册表

- **问题**：`importFromContent` 三步（writeFileSync → writeRegistry → loadAll）非事务；任一步抛错留下不一致状态。`deletePlugin` 同理（unlink → 删 registry entry → writeRegistry）。
- **证据**：
  - `mf-host.ts:249-259`：writeFileSync 在 249，writeRegistry 在 257，loadAll 在 258
  - `mf-host.ts:200-214`：unlinkSync 在 205，delete registry entry 在 210，writeRegistry 在 211
- **风险**：中
- **处置建议**：写盘先写 `.tmp` 后缀，注册表写成功再 rename；或捕获异常时回滚。
- **影响面**：安装失败/断电/磁盘满场景。
- **回退路径**：用户手动删除孤儿文件。
- **验收口径**：模拟 writeRegistry 抛错，userPluginsDir 不留 .tmp 文件。

### Bug 125 · 市场「已安装」判断按 file 名匹配，但 file 由 platform 推导

- **问题**：`isInstalled` 用 `p.file === entry.file` 匹配（`Settings.vue:458-460`）；但实际安装时 file 由 `evalPlugin` 探测 platform 生成（`mf-host.ts:236-243`），同名加 `-1/-2` 后缀（244-247）。manifest 里的 file 字段与实际安装 file 经常不一致 → 按钮永远显示「安装」而非「更新」。
- **证据**：
  - `Settings.vue:458-460` `plugins.value.find(p => p.file === file)`
  - `mf-host.ts:236-247` file 由 platform 推导
  - `mf-host.ts:400` manifest entry 原样透传，file 字段不一定存在
- **风险**：中
- **处置建议**：已安装判断改用 `sourceUrl === entry.url` 匹配（更稳定）；或 manifest 要求必须提供 file 字段。
- **影响面**：市场「更新」按钮可用性。
- **回退路径**：用户通过已安装列表的 refresh icon 更新。
- **验收口径**：安装后再打开市场，同一 entry 按钮显示「更新」。

### Bug 126 · 移动端 isInstalled 双匹配（file + name）在重名时失效

- **问题**：`mobile/Settings.vue:165-168` 先按 file 再按 name 匹配；mf-host 重名加 `-1/-2` 后缀后 file 不匹配，name 匹配可能误命中（两个插件同名）。
- **证据**：`mobile/Settings.vue:165-168`。
- **风险**：低
- **处置建议**：统一用 sourceUrl 匹配。
- **影响面**：移动端市场按钮状态。
- **回退路径**：同 Bug 125。
- **验收口径**：同上。
