# 第15轮调研 02：统一源市场形态——开源市场/商店形态取证

> 主题：为「星河音乐」把插件市场扩充为**统一源市场**（音源 / 插件 / 视频源单一入口，dshmark 形态）提供市场形态设计依据。
> 边界：本报告只取证开源/外部侧；D:\music\app 项目代码另有子代理负责，本文不引用、不修改。
> 证据标注：`文件:行号` = 已查证本地源码或官方文档原文；「一方称」= README/社区说法未逐行复核。
> 本轮重点：市场/商店**形态**本身（manifest schema、多镜像/多仓库、类型过滤、安装更新卸载原子性、失败降级），不重复第14轮已取证的导入引导/换源策略。

### 1. MusicFree（宿主：MusicFree-master；市场仓库：MusicFreePlugins-master）

| **更新机制** | 插件自报 `srcUrl`（写在插件 define 里，`types/plugin.d.ts:72`）；「更新全部」= 串行遍历 enabled 插件重拉各自 srcUrl（`pluginList.tsx:218-265`，`:227`）。**市场 list.json 不参与更新比对**。 |

| **失败友好文案** | HTTP 404 → 「插件不存在，请联系插件作者」（`index.ts:361-366`）；其他错误透传 message。 |
| **类型过滤** | **市场层无任何类型字段**；运行期过滤靠插件实例元数据：`getSearchablePlugins(supportedSearchType)` = enabled + `supportedMethods.has('search')` + `instance.supportedSearchType.includes(type)`（`index.ts:504-515`）。`supportedMethods` 是挂载时对 instance 所有函数键取 Set（`plugin.ts:993-995`）。 |
| **宿主兼容声明** | 插件 define 里 `appVersion` = semver range，挂载时 `satisfies(宿主版本, appVersion)` 不匹配 → 插件标记 VersionNotMatch（`plugin.ts:17,1019-1032`）——等价于 VS Code `engines.vscode`。 |
| **沙箱形态** | **无真隔离**：`Function(\`return function(require, __musicfree_require, module, exports, console, env, URL, process){${funcCode}}\`)()`（`plugin.ts:935-949`）；`require` 白名单包：axios/cheerio/crypto-js/dayjs/big-integer/qs/he/webdav（`:57-67`）；插件内 axios 默认超时 2000ms（`:36`）。 |

## 二、外部标杆精读（官方文档原文）

### 1. VS Code Marketplace

- **扩展唯一 id = `${publisher}.${name}`**；manifest 必填 `name / version(SemVer) / publisher / engines.vscode`，engines.vscode **不能写 `*`**（如 `^1.8.0` 表示最低兼容版本）。["https://code.visualstudio.com/api/references/extension-manifest"]
- **类型分类**：`categories` 受白名单约束（Programming Languages / Themes / Debuggers / Extension Packs …），`keywords` ≤30 个，市场内 `category:` / `tag:` 过滤，`@installed @updates @popular` 等过滤器组合。["https://code.visualstudio.com/docs/editor/extension-gallery"]
- **多市场配置**：产品级 `product.json` 的 `extensionsGallery` 块整换市场地址：`serviceUrl / itemUrl / resourceUrlTemplate / controlUrl / recommendationsUrl / nlsBaseUrl / publisherUrl`（第三方 fork 换市场即改这几个 URL）。["https://juejin.cn/post/7536084641448247359","https://juejin.cn/post/7400271712356712500"]
- **更新策略**：自动更新默认开启，发布后**延迟 12 小时**才装（`extensions.autoUpdateDelay`），可关（`autoCheckUpdates`），支持「安装指定旧版本」「预发布版本通道」。["https://code.visualstudio.com/docs/editor/extension-gallery"]
- **完整性**：市场签名发布，客户端验签，失败错误码族 `SignatureIsInvalid / EntryIsTampered / Untrusted / NotSigned …`；组织可用 `extensions.allowed` 做白名单。["https://code.visualstudio.com/docs/editor/extension-gallery"]
- **依赖**：`extensionDependencies`（装 A 带装 B）、`extensionPack`（捆绑包）。["https://code.visualstudio.com/api/references/extension-manifest"]

### 2. OctoPrint Plugin Repository

- **市场 = 静态索引**：`plugins.octoprint.org/plugins.json`，可配置替换（`plugins.pluginmanager.repository`）+ **缓存 TTL 秒数**（`repository_ttl` 默认 1440 = 24h）；另有 `notices.json` 公告流（独立 TTL 360）。["https://docs.octoprint.org/en/main/bundledplugins/pluginmanager.html"]
- **兼容声明两处**：包内 `__plugin_pythoncompat__ = ">=3.7,<4"`（不匹配宿主 Python 则拒绝加载）+ 仓库注册文件 front matter `compatibility.python`。["https://docs.octoprint.org/en/master/plugins/python3_migration.html"]
- **安装格式**：zip/tar.gz/whl 走 pip；单 .py 直接复制；**.json = URL 清单**（导出文件或手工 URL 列表批量装）。["https://docs.octoprint.org/en/main/bundledplugins/pluginmanager.html"]
- **发布通道**：stable_branch + prerelease_branches 多通道，用户自选。["https://docs.octoprint.org/en/1.11.8/plugins/distributing.html"]

### 3. Homebrew

- **formula = Ruby 文件即清单**：`desc / homepage / license(SPDX) / url(源码tarball) + sha256 / version / head(开发分支) / depends_on(带 :build/:test/:optional/:recommended 与 arch/macos 约束) / conflicts_with / revision / compatibility_version`。["https://docs.brew.sh/Formula-Cookbook"]
- **市场 = Git 仓库**：homebrew-core 本身是 Git 仓库（tap），`formulae.brew.sh` 由定时任务从仓库生成 JSON 索引供客户端查询；bottle = 预编译包按平台分发。["https://docs.brew.sh/Formula-Cookbook"]
- **值得借鉴**：`sha256` 强制写在清单里（下载即校验）；`compatibility_version` 显式记录依赖 ABI 兼容边界。

### 4. 音乐类统一市场先例

- **any-listen 扩展商店本身就是最贴近的先例**：音乐播放器宿主 + 统一商店（list.json 静态仓库）+ 插件承载多协议音源（GDStudio 一条插件聚合网易云/QQ/哔哩哔哩/YT Music/Spotify 等——已实地拉取其 list.json 确认）+ WebDAV 扩展 + 歌单列表提供方扩展，即「一个市场装多种东西」。
- **MusicFree 是第二先例**：市场订阅 JSON 可批量装任意 JS 插件（音源、B站视频源、WebDAV 都在同一 plugins.json 里，见第一节表）。
- **未发现**有成熟产品把「音源 / 视频源 / 通用插件」拆成三个一级市场再聚合——统一市场形态在音乐类里已是事实标准（一个市场、按插件自述能力区分用途）。【一方称：未穷尽所有小众播放器】

## 三、可借鉴机制清单

### M1. 市场 manifest 的最小字段集（从三个极端取交集）

- **开源要点**：MusicFree plugins.json 最寒酸（name/url/version 三字段）；any-listen list.json 中等（12 字段 + 详情页 sha256/download_url/时间戳）；VS Code/OctoPrint 最全（publisher/id/版本约束/分类/license/签名）。三者共同点：**id、显示名、版本、下载地址、作者/主页**；差异在「是否把校验信息（hash/签名/兼容版本）放进市场清单」。
- **星河适配**：星河统一市场的分发包 manifest 建议字段：`{ id, kind: 'lx-script'|'mf-plugin'|'video-source'|'general', name, description, author?, homepage?, icon?, version, download_url, sha256?, min_app_version?, platforms?, categories[], tags[], updated_at }`。其中 **kind 是统一市场的灵魂字段**——市场只管分发包与元数据，宿主读到 kind 后路由到对应 host（见第四节）。
- **次生问题**：kind 之外要不要再放「能力清单」（如 MusicFree 的 supportedSearchType / any-listen 的 contributes.resource）？建议 v1 不放，能力说明写在包内 manifest，市场页只做静态展示，避免市场与包内元数据双写不一致。

### M2. 多镜像/多仓库是客户端责任，不是 README 责任

- **开源要点**：any-listen 把镜像做成**客户端递归链**（raw→jsdelivr×3→用户 ghProxy 列表），失败自动换 host（`mirrorReuqest.ts:116-146`）；VS Code 把整个 gallery 做成 product.json 可换块；lx-music 反面：客户端无镜像，README 让用户手工拼代理前缀。
- **星河适配**：①市场默认地址 = 静态 JSON 仓库（GitHub raw/Gitee raw 双地址写入配置，可像 any-listen 一样做成「加速站点」用户设置项）；②客户端内置镜像回退列表，拉市场 list 时自动按链切换，用户无感知；③镜像机制做成 `fetchWithMirror(url)` 一个工具，市场拉取与插件包下载共用。
- **次生问题**：镜像切换要对用户可见（设置页显示「当前通过加速节点 X」），否则坏缓存时用户无从排查；镜像节点失效要定期（如 30 天）清理默认列表——ghProxy 类域名存活期很短。

### M3. 更新比对必须发生在「市场清单 vs 已装版本」，不能只靠插件自报

- **开源要点**：any-listen 商店 list.json 带 version，客户端 compareVersions 出红点（`onlineList.ts:94-107`）；VS Code `@updates` 过滤器同构；**MusicFree 的反面：市场 version 字段没人用，更新全靠插件自报 srcUrl**——用户不手动点「更新全部」就永远不知道新版存在（`pluginList.tsx:218-265`）。
- **星河适配**：市场条目必须带 version；宿主启动后后台比对一次（>24h 节流），有新版只推红点不自动覆盖；手动「立即检查」= skipCache 重拉 list。
- **次生问题**：不同协议的版本号格式不统一（lx 是自由文本如 v1.2.1、musicxx 是日期式 2026.1010.1、MusicFree 是 semver）——统一市场比对时按包内声明的 `versionScheme` 选比较器，或统一要求插件作者迁到 semver。

### M4. 安装/更新原子性：先验后写、备份回滚

- **开源要点**：any-listen 事务最完整——下载后先 sha256 校验（`shared/index.ts:226-232`）、解包后 id 一致性校验（`manage.ts:151-154`）、更新时备份→替换→失败 restore（`manage.ts:178-198`）、publicKey 连续校验（`:175`）；MusicFree 是「先写新文件再删旧文件」（`index.ts:326-336`）+ hash 去重 + 降级保护（`:302-321`），无回滚但旧文件在写新文件失败时天然保留。
- **星河适配**：单文件脚本类（lx/mf）走 MusicFree 模式即可（写临时文件→parse 冒烟→替换→旧文件进回收站）；多文件包类（video 源、未来扩展）走 any-listen 备份-回滚模式。两条铁律：①新版先 parse 冒烟通过才允许替换旧版；②同 id 重复安装一律拒，禁止静默覆盖。
- **次生问题**：回滚后要恢复 enabled 状态与用户配置（any-listen 保留 installedTimestamp、bump updatedTimestamp，`manage.ts:187-189`——星河照抄）；卸载时被正在播放的源占用 → 学 any-listen 软删除、下次启动清理。

### M5. 失败降级：市场拉取失败 ≠ 用户世界崩塌

- **开源要点**：any-listen 启动拉商店失败静默吞掉（`onlineList.ts:191-201`），但无磁盘缓存——重启前商店页空白；MusicFree 订阅刷新逐 URL 汇总失败原因给用户（`pluginList.tsx:180-197`）；OctoPrint 用 TTL 缓存（repository_ttl 24h）兜底旧索引。
- **星河适配**：①市场 list 拉取成功后写磁盘缓存，失败时「显示上次缓存的市场 + 顶部横幅提示离线」；②单条插件安装失败只失败单条，错误文案可操作（404→「地址不存在」，仿 MusicFree `index.ts:361-366`）；③镜像全部失败才报「无法连接市场，请检查网络或加速节点」。
- **次生问题**：缓存 list 要带版本过期时间（如 7 天），过期后即使在线也提示用户市场可能不是最新。

### M6. 类型过滤的正确位置

- **开源要点**：MusicFree/any-listen 的共同答案是——**市场层用声明式标签（categories/tags）做浏览过滤，运行层用能力清单（supportedSearchType / contributes.resource）做路由过滤**，两层不互相依赖。VS Code 同构（category 白名单 + activationEvents）。
- **星河适配**：统一市场首页 = 一个搜索框 + 三个一级 Tab（音源 / 视频源 / 插件）= 市场 manifest 的 `kind` 字段过滤；进入详情后按宿主协议展示各自的安装按钮。不要在市场层试图做「能力级」过滤。
- **次生问题**：kind 字段作者乱填怎么办？any-listen 的办法是商店侧人工审核（Git 仓库 PR）——星河初期自建市场也靠人工收录，不要指望客户端校验 kind。

## 四、多协议适配层差异表（「市场只管分发包，宿主按类型路由」落地依据）

| 维度 | lx 协议（落雪音源） | MusicFree 协议 | any-listen 扩展 | video 源（MF bilibili 插件先例） |
|---|---|---|---|---|
| **包形态** | 单 .js，头部块注释 JSDoc | 单 .js，`module.exports = define` | 多文件包（.tar 内 package.json 式 manifest） | 单 .js（同 MusicFree 形态） |
| **元数据来源** | 脚本注释头 5 字段（utils.ts:53-59） | define 对象全字段（plugin.d.ts:64-144） | 包内 manifest（extension.d.ts:109-140） | define.platform='bilibili' |
| **初始化事件** | `lx.send('inited',{sources})`（preload.js:247-251） | Function 包装内直接执行，无显式 init | 入口函数在 VM 内运行（shared/index.ts:141-144） | 同 MusicFree |
| **搜索** | **无**——只是 URL 解析器，搜索靠宿主内置平台 | `search(query, page, type) → {isEnd, data[]}`（plugin.d.ts:19-23） | contributes.resource 声明 musicSearch 能力，宿主按资源路由 | `searchAlbum`：视频当 album、分 P 当 track（第14轮 M5） |
| **取链函数** | `lx.on('request', ({source,action,info}) → string)` | `getMediaSource(musicItem, quality) → {url, headers?, userAgent?}` | resourceAction(musicUrl) | `getMediaSource` 返回 DASH 音频流 URL + headers |
| **取链返回值校验** | 必须 ≤2048 的 http(s) URL 字符串（preload.js:78） | 结构由宿主兜底（plugin.ts:268-289），headers 透传 | 宿主逐字段校验（resource.ts） | `{url, headers}`（referer/host 伪装） |
| **防盗链 headers** | **不支持**（返回值只有 URL） | 支持（headers/userAgent 字段） | 支持（resource 返回值） | **必须**（bilibili 源不放 referer 即不可播） |
| **沙箱形态** | 每源一个隐藏 BrowserWindow，contextIsolation（第14轮） | RN 内 Function 包装 + require 白名单（无真隔离） | VM isolateContext（多进程隔离） | 同 MusicFree |
| **宿主兼容声明** | 无 | `appVersion` semver range（plugin.ts:1019-1032） | `target_engine`（主版本对齐，shared/index.ts:83-99） | 无 |
| **版本比较** | 无市场比对，自报 updateAlert | compare-versions（index.ts:302-321） | compareVersions（onlineList.ts:101） | 无 |

**落地结论**：统一市场无需统一协议，只需：
1. 分发包 manifest 加 `kind` 字段（`lx-script` / `mf-plugin` / `video-source` / `native-ui`）；
2. 宿主按 kind 选择加载器：`lxHost`（BrowserWindow + window.lx API 模拟）、`mfHost`（Function 包装 + require shim）、`videoHost`（复用 mfHost，额外支持 `{url, headers}` 透传给播放器）；
3. 各协议的沙箱与校验差异留在 host 内部，市场层不感知。
**关键风险**：lx 协议不支持自定义播放 headers，意味着任何需要 referer 的源（B站等）在 lxHost 形态下天然不可播——视频源必须路由到 mfHost 形态，不能为了「统一」硬塞进 lxHost。

## 五、反模式提醒（踩坑清单）

1. **市场清单里写了 version 却不参与比对**（MusicFree `plugins.json` 有 version 字段、宿主完全不读）——用户看到的版本永远是包内自述，商店红点无从算起。星河清单 version 必须参与比对。
2. **把「无市场」当市场用**：lx-music 整个生态的「市场」是 README 里一列裸 URL（lx-source/README.md:20-105），用户手工复制。星河 dshmark 形态必须反过来：一个 JSON 清单 URL 即市场，客户端内置。
3. **启动拉市场失败即空白，无磁盘缓存**（any-listen `onlineList.ts:191-201`）——国内用户首次启动大概率拉不动 GitHub raw，按 any-listen 原样抄 = 首次启动市场页直接空。必须磁盘缓存 + 镜像链双兜底。
4. **hash 去重过粗**（MusicFree sha256(整文件)，注释改一个字 hash 就变、被判「新插件」而非「升级」）——星河去重应以「包内 id + 版本」为准，hash 仅用于安装完整性校验。
5. **商店分页在客户端 slice**（any-listen `onlineList.ts:134`）——插件上百个后 list.json 全量下载越来越重。星河若自建索引，预留服务端分页（page/limit 参数），即使 v1 也先把参数位留出来。
6. **安装后不做冒烟测试**：lx/MusicFree 导入即信任，坏脚本运行时才炸（MusicFree 靠运行后 PluginState.Error 标记）。星河导入新源后必须跑一次 search 探活，失败允许保留条目但标「初始化失败」（第14轮 M2 已述，此处强调这是统一市场的强制项而非可选项）。
7. **多市场订阅无顺序/去重概念**（MusicFree subscribeUrl 数组无依赖声明）——若星河未来允许多市场，同 id 包在不同市场出现时的优先级（先到先得/后到覆盖）要提前定规则，否则用户更新行为不可预测。
