多端断点矩阵

同一套代码，按宽度和设备类型自动切换布局。车机单独走车机专用布局，不按宽度判断。
设备分类 手机 Phone 竖屏宽度 < 600px
平板 Tablet 600px ~ 1024px（横/竖屏自适应）
桌面 Desktop ≥ 1024px（Windows / Linux / macOS 窗口化）
车机 Car 通过 UA / URL 参数 / 本地配置识别为车机，强制走车机布局
判定顺序 ① 先判断是否车机：UA 含 Android Automotive|automotive|CarBrowser|Tesla，或 URL ?platform=car，或本地配置 xinyuan_car=1 → 走车机布局，无视宽度。
② 否则按宽度断点：<600 手机 / 600~1024 平板 / ≥1024 桌面。
③ 平板 ≥900 宽且宽≥高视为横屏，走接近桌面的两栏布局；<900 竖屏走手机单列布局。
禁止不允许新增其他断点。核心功能全端一致（同一功能在任一端可用则其他端也必须可用，裁剪项除外）；操作方式与布局不强制统一，各端遵循平台惯例差异化设计（桌面键鼠、手机触屏手势、车机大按钮、平板横屏多栏），差异以第 4 章为准。
现状对照代码已实现 断点与车机判定在 src/platform/index.ts，判定顺序与本节一致。仅需复核：手机档 rotate 值必须按 1.2 节改为旋转（见 Bug 9）。

0.3

性能分级降级规则

判定条件满足任一即视为"低性能设备"：① hardwareConcurrency < 4；② 手机/平板/车机 UA；③ 用户在设置中手动开启省电模式 xinyuan_low_perf=on。
降级动作 ① 粒子数量：桌面 200 → 平板 80 → 手机 50 → 车机 0；
② 封面模糊（仅 cover 模式）：桌面 blur(30px) → 平板 blur(12px) → 手机 blur(8px) → 车机不显示封面；wallpaper 模式模糊上限同档位、手机 ≤12px；gradient/solid 无模糊成本；低性能档手机退化为纯渐变（见 4.7 背景四态）；
③ 舞台频谱柱数：桌面 64 → 平板 32 → 手机 16 窄条 → 车机不显示；
④ 低性能档位下粒子数量再压减至 ≤80。
车机特殊规则车机端强制关闭所有动效（粒子、频谱、模糊），封面不显示、只显示歌名文字，唱片不渲染。驾驶安全优先。
现状对照需修正 本表已删掉旧版"手机静态封面"表述——封面旋转不属于性能降级项，手机/平板/桌面必须旋转（见 1.2）。粒子、模糊、频谱的档位数字与 src/platform/index.ts 的 tierFor() 一致。

2.17 MV 音源协议扩展（特色 · 音源获取 MV）
结论通过音源获取 MV 已实测可行（2026-10-24）：网易云 4 档、QQ音乐 3 档直链可播；酷狗/酷我元数据可用、播放地址需签名/token（本期只展示元数据，播放走插件分发二期）；咪咕无稳定 MV 接口，本期放弃。「视频 + MV 聚合」为本项目特色模块，全部 CORE 必做（见 0.4）。
能力声明音源 JS 在 inited 中自声明 capabilities.mvSearch/mvBySong/mvBySinger/mvRank/mvUrl（学 MusicFree 自由 platform，不学落雪 source key 白名单锁死）。未声明即视为无 MV 能力，UI 自动隐藏 MV 入口。
宿主分发（C-17 落地）lx-host.ts 新增 dispatchMvSearch(platform, kw, page) / dispatchMvUrl(song, quality)，与 musicSearch/musicUrl 同构（候选源逐个试、15s 超时）；插件市场/订阅源沿用现有通道分发新 action。action 命名统一为 mvSearch/mvUrl（复用社区既有名，不再引入 video 造成三方语义分裂）。
方法签名 ① mvSearch(keyword, page) → {list: MvItem[], total}（MV 搜索，聚合页用）；
② mvBySong(song) → MvItem[]（歌曲→相关 MV，播放页 MV 按钮用，取首个命中）；
③ mvBySinger(singerId) → MvItem[] / mvRank() → MvItem[]（歌手 MV / MV 热榜，聚合页二期）；
④ mvUrl(item, quality) → {url, headers, userAgent, qualities[]}（防盗链头必须返回，学 MusicFree；qualities 为档位数组）。
MvItem 统一结构（N18 落地）{source:'bili'|'wy'|'qq'|'kg', sourceId, bvid?, title, author, cover, durationSec(秒 number), play, danmaku?, qualities:{qn,label,url}[]}。bvid 改 optional（B 站老数据兼容映射）；卡片组件统一用 source/cover/durationSec，不再读 bvid 当主键。
四源实现对照 ① 网易云：/api/cloudsearch/pc 返回 mv 字段（数字 MV id）→ /api/mv/detail?id= 返回 brs{240,480,720,1080} 四档 mp4，HTTP 206 可播；
② QQ音乐：smartbox 搜索返回含 vid 的 MV 条目 → musicu.fcg gosrf.Stream.MvUrlProxy/GetMvUrls（需带 comm:{ct:24,cv:4747474}）返回 3 档 mp4；
③ 酷狗：/api/v3/mv/list、/api/v3/mv/detail 元数据（mvhash/mkv_sd_hash/封面/时长），播放地址需签名接口（开源实现已覆盖，走插件分发）；
④ 酷我：搜索返回 MVFLAG/MVQUALITY/MVPIC 元数据，播放地址需 token 签名（走插件分发）。
档位收敛统一档位表 ≤6 档 {qn,label,url}：自动 / 240P / 480P / 720P / 1080P / 4K（按源返回有几个显示几个）；「自动」= 各源最高免登档。切换不重头播（复用 Bug 104 逻辑：切换前记 position，load 后 seek 回）。
防盗链播放地址统一走 swmedia 代理（N19 落地后）：mediaUrl(url, referer?) 包装 + media.ts:35-48 refererFor() 注入（已覆盖 126.net/163.com/gtimg.cn/qq.com，网易/QQ 零新增）；移动端走 /swmedia/?u=。
缓存键绝不能用 url 当键：mv_{source}_{id}_{quality}（sha1 化，参照 media.ts:172-174）。直链有时效（B 站 playurl 小时级、网易 brs / QQ GetMvUrls 同理），命中缓存即本地播放。
合规应用层设「仅元信息/解析地址」合规开关（默认开=允许播放）；沿用「用户自导入音源、应用不内置」模式；不内置任何第三方解析服务。

缓存/下载复用① 播放临时缓存：MV 边播边缓存（上限并入视频 1GB，见 1.12）；② 下载：MV 详情「下载」整片保存 MP4（含封面，文件名「歌手 - 歌名 - MV.mp4」，走 1.12 多线程+断点续传）；③ 离线缓存：整片下载离线可播（见 3.6，键 mv_{source}_{id}_{quality}）。

4.8 局域网同步（无服务器 · 第四轮调研细化）
目标无任何服务器，同一局域网/热点下 桌面 ↔ 手机/平板/车机 同步：我喜欢的音乐、播放历史、歌单收藏、设置项、EQ 预设、播放进度断点；不同步音频文件本身（曲库另走下载/缓存）。
架构桌面宿主 + 组播发现 + 二维码配对：
① 宿主：Win 桌面 Electron 主进程常驻，内嵌 Node http + ws + 自签 TLS（sync_client 的 Dart WS 客户端逻辑可移植 TS）；
② 发现：纯 JS 组播 Announce（LocalSend 式 UDP 224.0.0.167:53317）+ IP 段扫描回退（192.168/10.x HTTP 探测），避开 Win10 原生不解析 .local 的问题；iOS/Android 原生扫码连接，车机 WebView 手输 IP:端口（WebView 不解析 .local，Chrome 本地网络访问权限会拦网页私网 IP）；
③ 配对：二维码编码 host:port + 一次性 challenge（16~32B），proof=HMAC(secret, sid|nonce|ts) 验签 + SHA-256 证书指纹比对防 MITM（密钥层复用 sync_client 的 scrypt+AES-GCM）；
④ 冲突：LWW + 墓碑（记录带 updatedAt，时钟漂移用 Lamport/设备 ID 兜底，删除写墓碑）；收藏/播放记录天然追加型冲突最少。
